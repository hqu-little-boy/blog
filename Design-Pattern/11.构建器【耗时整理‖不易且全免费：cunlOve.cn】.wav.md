# Builder 模式（构建器）

## 一、模式概述

Builder 模式属于**对象创建型模式**，主要用于**分步骤构建一个复杂对象**。

### 核心思想

> 将一个复杂对象的**构建**与其**表示**分离，使得同样的构建过程可以创建不同的表示。

### 解决的问题

在软件系统中，有时面临一个**大型、复杂对象**的创建工作。该对象通常由各个子对象以一定的算法/流程构成。由于需求变化，复杂对象的**各个部分经常面临剧烈变化**，但将它们**组合在一起的算法/流程却相对稳定**。

**关键词**：一部分是**变化**的，一部分是**稳定**的。

> 这与 Template Method 模式的思想非常相似 —— 稳定的流程骨架 + 变化的具体步骤。但 Builder 模式的关注点在于**对象的创建工作**。

---

## 二、经典案例：建房子

以游戏场景中"建房子"为例：

- 建造流程（**稳定**）：地基 → 墙壁 → 窗户 → 门 → 屋顶
- 各步骤的具体实现（**变化**）：
  - 石头房：混凝土地基、石墙、铁框窗户、铁门、瓦片屋顶
  - 茅草房：夯实土地基、竹篱墙、纸窗、木门、茅草屋顶

## 三、核心要点：构造函数中不能调用虚函数

这是 C++ 中 Builder 模式的一个关键问题，也是将构建逻辑从构造函数中移出的根本原因。

### 为什么不能在构造函数中调用虚函数？

在 C++ 中，构造函数内调用虚函数执行的是**静态绑定**（调用当前类的版本），而非**动态绑定**（调用子类的 override 版本）。

**原因**：C++ 对象的构造顺序是先调用父类构造函数，再调用子类构造函数。如果允许在父类构造函数中通过动态绑定调用子类的虚函数 override 版本，就会出现：**子类尚未构造完成，子类的虚函数已被调用** —— 这违背了对象的基本伦理（必须先诞生，才能行使行为）。

> **注意**：Java 和 C# 中构造函数内调用虚函数是动态绑定的，语言设计不同。

### 正确做法

将构建逻辑放在一个独立的 `init()` 方法中（而非构造函数），此时对象已完整构造，虚函数表已正确初始化，动态绑定正常工作。

```cpp
// 错误：构造函数中调用虚函数（静态绑定，不调用子类版本）
class House {
public:
    House() {
        buildPart1();  // 只会调用 House::buildPart1()，不会调用子类override
        buildPart2();
    }
    virtual void buildPart1() = 0;  // 纯虚函数！行为未定义
    virtual void buildPart2() = 0;
};

// 正确：用 init() 代替构造函数
class House {
public:
    void init() {
        buildPart1();  // 动态绑定，正确调用子类版本
        buildPart2();
    }
protected:
    virtual void buildPart1() = 0;
    virtual void buildPart2() = 0;
};
```

**运行验证**：

```
=== 错误示范：构造函数中调用虚函数 ===
创建 DerivedBad 对象：
[Base] step1       ← 父类构造函数中调用的是Base版本（静态绑定）
[Base] step2
[Derived] step1    ← 子类构造函数中才调用Derived版本
[Derived] step2

=== 正确做法：用 init() 代替构造函数 ===
创建 DerivedGood 对象并调用 init()：
[DerivedGood] 执行步骤1   ← 正确调用子类版本
[DerivedGood] 执行步骤2
```

## 四、Builder 模式的演进

### 版本一：基础版（无 Director）

最简单的 Builder 模式实现：抽象构建器定义构建步骤（纯虚函数），具体构建器 override 各步骤，`init()` 方法按固定流程调用各步骤。

```
┌──────────────────┐       ┌──────────────────────┐
│     House        │       │   HouseBuilder       │
│──────────────────│       │──────────────────────│
│ - foundation     │       │ # pHouse: House*     │
│ - wall           │◄──────│──────────────────────│
│ - window         │ 持有   │ + init()             │
│ - door           │       │ + buildFoundation()* │
│ - roof           │       │ + buildWall()*       │
│──────────────────│       │ + buildWindow()*     │
│ + show()         │       │ + buildDoor()*       │
└──────────────────┘       │ + buildRoof()*       │
                           │ + getResult()        │
                           └──────────┬───────────┘
                                      │ 继承
                        ┌─────────────┴─────────────┐
                        │                           │
              ┌─────────┴─────────┐     ┌───────────┴──────────┐
              │ StoneHouseBuilder  │     │ StrawHouseBuilder     │
              │───────────────────│     │───────────────────────│
              │ buildFoundation() │     │ buildFoundation()     │
              │ buildWall()       │     │ buildWall()           │
              │ buildWindow()     │     │ buildWindow()         │
              │ buildDoor()       │     │ buildDoor()           │
              │ buildRoof()       │     │ buildRoof()           │
              └───────────────────┘     └───────────────────────┘
```

**客户端使用**：

```cpp
StoneHouseBuilder builder;
builder.init();              // 按固定流程构建
House* house = builder.getResult();
```

### 版本二：完整版（含 Director）

当对象过于复杂时，可以将构建过程（`init()` 的流程逻辑）进一步从 Builder 中分离出来，放到一个独立的 **Director** 类中。

- **Builder**：负责每一步的具体实现（变化的部分）
- **Director**：负责构建步骤的顺序和流程逻辑（稳定的部分）

```
┌─────────────────┐         ┌──────────────────────┐
│  HouseDirector   │         │   HouseBuilder       │
│─────────────────│         │──────────────────────│
│ - pBuilder ──────┼────────►│ # pHouse: House*     │
│─────────────────│  持有    │──────────────────────│
│ + setBuilder()  │         │ + initProduct()      │
│ + construct()   │         │ + buildFoundation()* │
│   (稳定流程)     │         │ + buildWall()*       │
└─────────────────┘         │ + buildWindow()*     │
                            │ + buildDoor()*       │
                            │ + buildRoof()*       │
                            │ + getResult()        │
                            └──────────┬───────────┘
                                       │ 继承
                         ┌─────────────┴─────────────┐
                 ┌───────┴───────┐         ┌─────────┴────────┐
                 │StoneHouseBuilder│        │StrawHouseBuilder  │
                 └───────────────┘         └──────────────────┘
```

**客户端使用**：

```cpp
HouseDirector director;

StoneHouseBuilder stoneBuilder;
director.setBuilder(&stoneBuilder);
House* stoneHouse = director.construct();  // Director指挥构建流程
```

### 何时拆分 Director？

| 情况 | 建议 |
|------|------|
| 构建流程简单 | 不需要 Director，Builder 自带 `init()` 即可 |
| 构建流程复杂 / 需要多种构建策略 | 引入 Director，将流程逻辑分离 |
| 类过于庞大（"胖类"） | 拆分：类本身（状态+行为）vs 类的构建部分 |
| 类较简单 | 合并即可 |

> **重构原则**：类越来越复杂就拆拆拆，类越来越简单就合并合并。Builder 和 Director 可以合并也可以分离，取决于类的复杂度。

## 五、模式定义与结构

### GoF 定义

> 将一个复杂对象的**构建**与它的**表示**分离，使得同样的构建过程可以创建不同的表示。

### 参与者

| 角色 | 职责 |
|------|------|
| **Builder（抽象构建器）** | 定义创建产品各部件的抽象接口 |
| **ConcreteBuilder（具体构建器）** | 实现 Builder 接口，定义各部件的具体构建方式；提供获取产品的接口 |
| **Director（指挥者）** | 使用 Builder 接口按步骤构建产品（可选，视复杂度而定） |
| **Product（产品）** | 被构建的复杂对象 |

### 稳定 vs 变化

| 部分 | 性质 | 说明 |
|------|------|------|
| Director 中的构建流程 | **稳定** | `construct()` 中步骤顺序固定 |
| Builder 中的各构建步骤 | **变化** | 各子类 override 不同实现 |
| Builder 的接口（参数、返回值） | **稳定** | 虚函数签名不变 |

---

## 六、适用场景与优缺点

### 适用场景

- 当创建复杂对象的算法应该独立于该对象的组成部分及其装配方式时
- 当构造过程必须允许被构造的对象有不同的表示时
- 当对象各部分的需求频繁变动，但组装流程相对稳定时

### 优点

- **封装性好**：客户端不必知道产品内部组成的细节
- **解耦**：将构建与表示分离，易于扩展新的产品类型
- **精细化控制**：构建过程分步骤进行，可精确控制产品构建流程
- **符合开闭原则**：增加新的具体 Builder 无需修改已有代码

### 缺点

- **难以应对构建流程（算法）的变动**：`construct()` 如果不稳定，需要额外处理（如将其改为虚函数，再通过子类扩展）
- **增加类数量**：需要创建 Builder、ConcreteBuilder 等多个类
- **适用范围有限**：仅适用于产品具有较多共同点、构建步骤相似的场景

---

## 七、Builder 与 Template Method 的关系

两者非常相似，都体现了"稳定的流程骨架 + 变化的具体步骤"的思想：

| 对比项 | Template Method | Builder |
|--------|----------------|---------|
| 关注点 | 算法流程的复用 | 复杂对象的**创建** |
| 稳定部分 | 模板方法（基类中的非虚函数） | Director 中的构建流程 / Builder 中的 `init()` |
| 变化部分 | 虚函数（子类 override） | 各构建步骤（子类 override） |
| 产出 | 无明确产出（执行算法） | 一个完整的复杂对象（Product） |
| 适用场景 | 算法骨架相同、部分步骤不同 | 对象构建流程相同、各部分实现不同 |

---

## 八、与其他语言的对比

| 特性 | C++ | Java / C# |
|------|-----|-----------|
| 构造函数中调用虚函数 | **静态绑定**（调用当前类版本） | **动态绑定**（调用子类 override 版本） |
| Builder 需要 `init()` | **是**（构造函数中虚函数不生效） | **否**（可直接在构造函数中调用） |
| 原因 | 子类构造前父类构造，先诞生后行为 | 语言设计不同，允许构造期多态 |

## 九、示例代码

### 示例一：基础 Builder（无 Director）

```cpp
#include <iostream>
#include <string>
#include <memory>

// ===================== 产品类 =====================
class House {
public:
    void setFoundation(const std::string& f) { foundation = f; }
    void setWall(const std::string& w) { wall = w; }
    void setWindow(const std::string& w) { window = w; }
    void setDoor(const std::string& d) { door = d; }
    void setRoof(const std::string& r) { roof = r; }

    void show() const {
        std::cout << "=== 房屋信息 ===" << std::endl;
        std::cout << "  地基: " << foundation << std::endl;
        std::cout << "  墙壁: " << wall << std::endl;
        std::cout << "  窗户: " << window << std::endl;
        std::cout << "  门:   " << door << std::endl;
        std::cout << "  屋顶: " << roof << std::endl;
    }

private:
    std::string foundation;
    std::string wall;
    std::string window;
    std::string door;
    std::string roof;
};

// ===================== 抽象构建器 =====================
class HouseBuilder {
public:
    virtual ~HouseBuilder() = default;

    virtual void buildFoundation() = 0;
    virtual void buildWall() = 0;
    virtual void buildWindow() = 0;
    virtual void buildDoor() = 0;
    virtual void buildRoof() = 0;

    House* getResult() { return pHouse.get(); }

    // 注意：不能放在构造函数中（C++构造函数中虚函数静态绑定）
    void init() {
        pHouse = std::make_unique<House>();
        buildFoundation();
        buildWall();
        buildWindow();
        buildDoor();
        buildRoof();
    }

protected:
    std::unique_ptr<House> pHouse;
};

// ===================== 具体构建器：石头房 =====================
class StoneHouseBuilder : public HouseBuilder {
protected:
    void buildFoundation() override {
        std::cout << "[石头房] 浇筑混凝土地基" << std::endl;
        pHouse->setFoundation("混凝土地基");
    }
    void buildWall() override {
        std::cout << "[石头房] 砌石墙" << std::endl;
        pHouse->setWall("石墙");
    }
    void buildWindow() override {
        std::cout << "[石头房] 安装铁框窗户" << std::endl;
        pHouse->setWindow("铁框窗户");
    }
    void buildDoor() override {
        std::cout << "[石头房] 安装铁门" << std::endl;
        pHouse->setDoor("铁门");
    }
    void buildRoof() override {
        std::cout << "[石头房] 铺设瓦片屋顶" << std::endl;
        pHouse->setRoof("瓦片屋顶");
    }
};

// ===================== 具体构建器：茅草房 =====================
class StrawHouseBuilder : public HouseBuilder {
protected:
    void buildFoundation() override {
        std::cout << "[茅草房] 夯实地基" << std::endl;
        pHouse->setFoundation("夯实土地基");
    }
    void buildWall() override {
        std::cout << "[茅草房] 编织竹篱墙" << std::endl;
        pHouse->setWall("竹篱墙");
    }
    void buildWindow() override {
        std::cout << "[茅草房] 安装纸窗" << std::endl;
        pHouse->setWindow("纸窗");
    }
    void buildDoor() override {
        std::cout << "[茅草房] 安装木门" << std::endl;
        pHouse->setDoor("木门");
    }
    void buildRoof() override {
        std::cout << "[茅草房] 铺设茅草屋顶" << std::endl;
        pHouse->setRoof("茅草屋顶");
    }
};

// ===================== 客户端代码 =====================
int main() {
    std::cout << ">>> 构建石头房 <<<" << std::endl;
    StoneHouseBuilder stoneBuilder;
    stoneBuilder.init();
    stoneBuilder.getResult()->show();

    std::cout << std::endl;

    std::cout << ">>> 构建茅草房 <<<" << std::endl;
    StrawHouseBuilder strawBuilder;
    strawBuilder.init();
    strawBuilder.getResult()->show();

    return 0;
}
```

### 示例二：含 Director 的完整版

```cpp
#include <iostream>
#include <string>
#include <memory>

// ===================== 产品类 =====================
class House {
public:
    void setFoundation(const std::string& f) { foundation = f; }
    void setWall(const std::string& w) { wall = w; }
    void setWindow(const std::string& w) { window = w; }
    void setDoor(const std::string& d) { door = d; }
    void setRoof(const std::string& r) { roof = r; }

    void show() const {
        std::cout << "=== 房屋信息 ===" << std::endl;
        std::cout << "  地基: " << foundation << std::endl;
        std::cout << "  墙壁: " << wall << std::endl;
        std::cout << "  窗户: " << window << std::endl;
        std::cout << "  门:   " << door << std::endl;
        std::cout << "  屋顶: " << roof << std::endl;
    }

private:
    std::string foundation;
    std::string wall;
    std::string window;
    std::string door;
    std::string roof;
};

// ===================== 抽象构建器 =====================
class HouseBuilder {
public:
    virtual ~HouseBuilder() = default;

    virtual void buildFoundation() = 0;
    virtual void buildWall() = 0;
    virtual void buildWindow() = 0;
    virtual void buildDoor() = 0;
    virtual void buildRoof() = 0;

    virtual void initProduct() { pHouse = std::make_unique<House>(); }
    House* getResult() { return pHouse.get(); }

protected:
    std::unique_ptr<House> pHouse;
};

// ===================== 具体构建器：石头房 =====================
class StoneHouseBuilder : public HouseBuilder {
public:
    void buildFoundation() override {
        std::cout << "[石头房] 浇筑混凝土地基" << std::endl;
        pHouse->setFoundation("混凝土地基");
    }
    void buildWall() override {
        std::cout << "[石头房] 砌石墙" << std::endl;
        pHouse->setWall("石墙");
    }
    void buildWindow() override {
        std::cout << "[石头房] 安装铁框窗户" << std::endl;
        pHouse->setWindow("铁框窗户");
    }
    void buildDoor() override {
        std::cout << "[石头房] 安装铁门" << std::endl;
        pHouse->setDoor("铁门");
    }
    void buildRoof() override {
        std::cout << "[石头房] 铺设瓦片屋顶" << std::endl;
        pHouse->setRoof("瓦片屋顶");
    }
};

// ===================== 具体构建器：茅草房 =====================
class StrawHouseBuilder : public HouseBuilder {
public:
    void buildFoundation() override {
        std::cout << "[茅草房] 夯实地基" << std::endl;
        pHouse->setFoundation("夯实土地基");
    }
    void buildWall() override {
        std::cout << "[茅草房] 编织竹篱墙" << std::endl;
        pHouse->setWall("竹篱墙");
    }
    void buildWindow() override {
        std::cout << "[茅草房] 安装纸窗" << std::endl;
        pHouse->setWindow("纸窗");
    }
    void buildDoor() override {
        std::cout << "[茅草房] 安装木门" << std::endl;
        pHouse->setDoor("木门");
    }
    void buildRoof() override {
        std::cout << "[茅草房] 铺设茅草屋顶" << std::endl;
        pHouse->setRoof("茅草屋顶");
    }
};

// ===================== 指挥者（Director）=====================
// 将稳定的构建流程从 Builder 中分离出来
// Director 负责构建步骤的顺序和逻辑，Builder 负责每一步的具体实现
class HouseDirector {
public:
    void setBuilder(HouseBuilder* b) { pBuilder = b; }

    // 稳定的构建流程（非虚函数，不可变）
    House* construct() {
        pBuilder->initProduct();
        pBuilder->buildFoundation();
        pBuilder->buildWall();
        pBuilder->buildWindow();
        pBuilder->buildDoor();
        pBuilder->buildRoof();
        return pBuilder->getResult();
    }

private:
    HouseBuilder* pBuilder;
};

// ===================== 客户端代码 =====================
int main() {
    HouseDirector director;

    std::cout << ">>> Director 指挥构建石头房 <<<" << std::endl;
    StoneHouseBuilder stoneBuilder;
    director.setBuilder(&stoneBuilder);
    House* stoneHouse = director.construct();
    stoneHouse->show();

    std::cout << std::endl;

    std::cout << ">>> Director 指挥构建茅草房 <<<" << std::endl;
    StrawHouseBuilder strawBuilder;
    director.setBuilder(&strawBuilder);
    House* strawHouse = director.construct();
    strawHouse->show();

    return 0;
}
```

## 十、总结

1. Builder 模式的核心是**分步骤构建复杂对象**，构建流程稳定，各步骤实现可变
2. C++ 中**不能在构造函数中调用虚函数**（静态绑定），因此必须用独立的 `init()` 方法
3. Director 是可选的，当构建逻辑复杂时将其从 Builder 中分离；简单场景可省略
4. Builder 模式与 Template Method 思想相似，但 Builder 关注的是**对象创建**
5. 设计模式的核心：从变化中找到稳定，将变化封装，用稳定支撑架构
