# 设计模式总结

## 一、核心目标：管理变化，提高复用

学习设计模式的最大误区是把它当作算法或数据结构来学——只分析结构、理解调用流程。这只是最初步的学习，远远不够。

**设计模式的核心目标**：通过管理变化来提高代码的复用性。

- 如果代码写的都对，但场景本身没有复用的必要性，那就是误用模式
- 照猫画虎式地写代码，可能与复用性的目标南辕北辙

## 二、两大手段：分解与抽象

### 分解（Decomposition）

面向对象设计的第一步是分解。就像小孩子认识世界：先知道"这是梨、这是苹果、这是香蕉"——建立分解的思维，知道事物之间的不同。

在程序中，我们先识别出 `Line`、`Rectangle`、`Circle` 等不同的具体类型。

### 抽象（Abstraction）

分解之后，需要建立抽象思维。就像小孩子后来知道"这一类都属于水果"。在程序中，我们针对抽象进行统一处理——所有形状都有共同的特征（如面积、周长），交通工具也有共同的抽象特征。

**软件设计的思维模型与人认识世界的规律高度类似。**

## 三、八大设计原则

八大原则比任何一个具体模式都重要得多，需要内化为一种认知能力。

| 原则 | 全称 | 核心要点 |
|------|------|----------|
| **SRP** | 单一职责原则 (Single Responsibility Principle) | 一个类只负责一项职责 |
| **OCP** | 开闭原则 (Open-Closed Principle) | 对扩展开放，对修改关闭 |
| **LSP** | 里氏替换原则 (Liskov Substitution Principle) | 子类必须能替换父类 |
| **ISP** | 接口隔离原则 (Interface Segregation Principle) | 不应强迫客户依赖不需要的接口 |
| **DIP** | 依赖倒置原则 (Dependency Inversion Principle) | 依赖抽象而非具体 |
| **CRP** | 合成复用原则 (Composite Reuse Principle) | 优先使用组合而非继承 |
| **LoD** | 迪米特法则 (Law of Demeter) | 最少知识原则，减少对象间的了解 |
| **——** | 高内聚低耦合 | 模块内部紧密关联，模块之间松散依赖 |

### 原则之间的关联

这些原则是相辅相成的：

- 违背**依赖倒置原则**时，往往同时违背了**开闭原则**
- 违背**单一职责原则**时，通常**依赖倒置原则**也会违背
- Strategy 模式违背了**开闭原则**（枚举类型需要修改已有代码）
- Decorator 模式违背了**单一职责原则**（一个类承担了多种装饰职责）

## 四、五大重构技法

在具体设计实现时，通过重构的方式迭代设计。从更高层次来看，有五种核心技法：

| 重构方向 | 说明 |
|----------|------|
| 静态 → 动态 | 静态绑定转为动态绑定（多态） |
| 早绑定 → 晚绑定 | 编译期确定转为运行期确定 |
| 继承 → 组合 | 慎用继承，多用组合 |
| 编译时依赖 → 运行时依赖 | 降低编译期耦合 |
| 紧耦合 → 松耦合 | 通过间接层增加灵活性 |

这五种技法相辅相成，有些技法之间是相通的。

## 五、C++ 对象模型与设计模式的映射

这是本节课最核心的洞察。

### 三种对象模型

```
结构1: 直接继承        结构2: 组合对象(值)      结构3: 组合指针(引用)
┌─────────────┐      ┌─────────────┐         ┌─────────────┐
│     A       │      │     A       │         │     A       │
│ ┌─────────┐ │      │ ┌─────────┐ │         │ ┌───┐       │
│ │   B     │ │      │ │   B     │ │         │ │ p │──────►│ B/B1/B2/...
│ └─────────┘ │      │ └─────────┘ │         │ └───┘       │
└─────────────┘      └─────────────┘         └─────────────┘
  紧耦合                紧耦合                   松耦合
  B固定不变             B固定不变(切割)           可指向B的任意子类
```

### 关键结论

- **结构1（继承）和结构2（值组合）**：在 C++ 内存模型上几乎没有区别，B 的数据成员都嵌入在 A 对象的内存前端
- **结构3（指针组合）**：通过指针间接引用多态对象，提供极大的灵活性——可以指向 B，也可以指向 B 的子类 B1、B2、B3...
- **几乎所有设计模式的结构都归属到第三种**——通过指针指向多态对象来表达灵活性

### 为什么不用值组合？

值组合会带来**对象切割（Object Slicing）**问题：将子类对象赋值给基类变量时，子类特有的部分会被"切掉"，只保留基类部分。

### 为什么说"慎用继承，多用组合"？

这里的"组合"不是指值组合（结构2），而是指针组合（结构3）。指针组合才能实现多态和松耦合。

## 六、封装变化：模式分类

侯捷老师提出的分类视角——从"封装变化点"的角度理解模式：

### 依然非常常用的模式（重点掌握）

| 模式 | 封装的变化 |
|------|-----------|
| **Strategy** | 算法/策略的变化 |
| **Observer** | 一对多依赖关系的变化 |
| **Decorator** | 功能组合的变化 |
| **Template Method** | 算法骨架中某些步骤的变化 |
| **Factory Method** | 对象创建的变化 |
| **Adapter** | 接口不兼容的变化 |
| **Bridge** | 实现与抽象的独立变化 |
| **Proxy** | 访问控制的变化 |
| **Composite** | 树形结构中"部分-整体"的变化 |

### 现代 C++ 中不太常用的模式

| 模式 | 被替代的原因 |
|------|-------------|
| **Builder** | 现代语言特性（初始化列表、移动语义）简化了复杂对象构建 |
| **Mediator** | 场景较少，通常用事件系统或消息队列替代 |
| **Memento** | 被序列化方案（如 JSON、Protobuf）替代 |
| **Iterator** | C++ 模板和泛型编程提供了更灵活的编译期多态迭代器 |
| **Chain of Responsibility** | 直接用数据结构（如 `std::vector`）表达即可 |
| **Visitor** | 前提条件苛刻，要么不用，要用就要慎重使用 |
| **Command** | C++ 的函数对象（`std::function`）和 Lambda 表达式提供了更好的替代 |
| **Interpreter** | 复杂场景通常用开源工具（如 ANTLR）替代 |

## 七、变化点与稳定点

每个设计模式都有其**稳定点**和**变化点**：

- **稳定点**：模式能够正常工作的前提条件
- **变化点**：模式通过多态、组合等手段来封装和隔离的部分

### 当稳定点不稳定了怎么办？

如果模式所依赖的稳定点发生了变化，该模式就不再适用，需要辗转到其他模式来解决。这说明没有万能的模式。

### 两种极端情况

- **所有都是变化点**：任何模式或模式组合都无法解决
- **所有都是稳定点**：设计模式没有用武之地

**正常的软件符合正态分布**：变化点和稳定点交错出现、交织在一起。设计模式最大的艺术就是把变化点和稳定点拆干净、隔离起来。

## 八、什么时候不用设计模式

| 场景 | 原因 |
|------|------|
| **代码可读性很差** | 先把命名、类结构、逻辑划分理清楚，模式是在这之后才做的 |
| **需求理解很浅** | 先写出最初版本，随着迭代加深理解后再引入模式 |
| **变化没有显现** | 不要做不恰当的预测，变化出现后再用模式 |
| **非系统关键依赖点** | 优先在关键模块使用模式，非关键点可以先放一放 |
| **一次性项目** | 外包软件等不维护的项目，复用价值无法体现 |
| **项目即将发布** | 急匆匆上模式可能引入 bug，首先要保证逻辑正确性 |

**不要为模式而模式。** 产品型公司的软件需要长期维护迭代，设计模式的价值才能充分体现。

## 九、关注抽象类和接口

写抽象类的人水平一般较高——表达的是设计能力。写具体子类是更低层次的工作。

**建议**：中国的程序员应该多写基类、抽象类、接口，不要天天只写具体子类。绩效考核不应该用代码行数来衡量。

## 十、Framework 与 Application 的区隔思维

| 角色 | 关注点 | 设计模式的理解层次 |
|------|--------|-------------------|
| **应用开发人员** | 使用框架提供的扩展点 | 能识别模式、使用模式 |
| **框架开发人员** | 为应用设计扩展点和接口 | 深度理解模式、设计模式 |

类比：应用开发人员像"会开车的人"，框架开发人员像"会造车的人"。造车需要对引擎、离合器等有更深度的理解。

## 十一、良好的设计是演化的结果

不要追求一步到位。实际工作中，设计的演化通常以**周甚至月为单位**迭代，通过重构的方式渐进演化，而非急风骤雨般的改变。

## 十二、设计模式学习的四个阶段

借用剑道的类比：

| 阶段 | 状态 | 说明 |
|------|------|------|
| 第一阶段 | **手中无剑，心中无剑** | 见到模式不知道它是某种模式 |
| 第二阶段 | **手中有剑，心中无剑** | 能识别模式、照猫画虎地使用（应用开发人员） |
| 第三阶段 | **手中有剑，心中有剑** | 深度理解模式，能设计框架、为他人留扩展点（框架开发人员，通常需要3-8年经验） |
| 第四阶段 | **手中无剑，心中有剑** | 忘掉具体模式，心中只有原则，可以发明新模式 |

> 第四阶段不追求代码结构一定是某个模式，只要符合设计原则、解决耦合性问题、提高复用性，就是模式的一种应用。

## 附录：关键概念示例代码

### 示例1：C++ 对象模型三种结构

```cpp
#include <iostream>
#include <string>

// 基类 B
class B {
public:
    virtual ~B() = default;
    virtual std::string name() const { return "B"; }
    virtual void doSomething() const {
        std::cout << "B::doSomething()" << std::endl;
    }
};

class B1 : public B {
public:
    std::string name() const override { return "B1"; }
    void doSomething() const override {
        std::cout << "B1::doSomething()" << std::endl;
    }
};

class B2 : public B {
public:
    std::string name() const override { return "B2"; }
    void doSomething() const override {
        std::cout << "B2::doSomething()" << std::endl;
    }
};

// 结构1: A 继承 B (紧耦合)
class A_Inherit : public B {
public:
    std::string name() const override { return "A_Inherit"; }
    void doSomething() const override {
        std::cout << "A_Inherit: 通过继承获得B的能力" << std::endl;
    }
};

// 结构2: A 组合 B 对象(值语义, 紧耦合)
class A_ComposeValue {
    B b_;  // 值语义: B无法被替换为子类, 会发生对象切割
public:
    void doSomething() const {
        std::cout << "A_ComposeValue: ";
        b_.doSomething();
    }
};

// 结构3: A 组合 B 指针(引用语义, 松耦合)
// 几乎所有设计模式都采用此结构
class A_ComposePointer {
    B* pb_;  // 指针可以指向B或B的任意子类
public:
    explicit A_ComposePointer(B* pb) : pb_(pb) {}
    void doSomething() const {
        std::cout << "A_ComposePointer: ";
        pb_->doSomething();  // 多态调用
    }
};

// 对象切割(Object Slicing)演示
void demonstrateSlicing() {
    std::cout << "=== 对象切割演示 ===" << std::endl;
    B1 b1;
    B& ref = b1;   // 引用: 保持多态
    B  val = b1;   // 值拷贝: 发生切割

    std::cout << "通过引用调用: ";
    ref.doSomething();  // B1::doSomething()
    std::cout << "通过值拷贝调用(切割后): ";
    val.doSomething();  // B::doSomething() — 切割!
}

int main() {
    std::cout << "=== C++ 对象模型三种结构 ===" << std::endl;

    // 结构1: 继承
    A_Inherit a1;
    a1.doSomething();

    // 结构2: 组合对象(值语义)
    A_ComposeValue a2;
    a2.doSomething();

    // 结构3: 组合指针(引用语义) — 多态, 灵活
    B  b;
    B1 b1;
    B2 b2;
    A_ComposePointer a3_b(&b);
    A_ComposePointer a3_b1(&b1);
    A_ComposePointer a3_b2(&b2);

    a3_b.doSomething();   // B::doSomething()
    a3_b1.doSomething();  // B1::doSomething()
    a3_b2.doSomething();  // B2::doSomething()

    demonstrateSlicing();
    return 0;
}
```

**运行输出：**
```
=== C++ 对象模型三种结构 ===
A_Inherit: 通过继承获得B的能力
A_ComposeValue: B::doSomething()
A_ComposePointer: B::doSomething()
A_ComposePointer: B1::doSomething()
A_ComposePointer: B2::doSomething()
=== 对象切割演示 ===
通过引用调用: B1::doSomething()
通过值拷贝调用(切割后): B::doSomething()
```

### 示例2：Strategy 模式——枚举 vs 多态

```cpp
#include <iostream>

// 反面: 枚举方式 (违背开闭原则OCP)
enum class TaxType { Domestic, Foreign, Free };

double calculateTax_bad(double price, TaxType type) {
    switch (type) {
        case TaxType::Domestic: return price * 0.13;
        case TaxType::Foreign:  return price * 0.05;
        case TaxType::Free:     return 0.0;
        // 每次新增税率都要修改此函数
    }
    return 0.0;
}

// 正面: Strategy 模式 (符合开闭原则)
class TaxStrategy {
public:
    virtual ~TaxStrategy() = default;
    virtual double calculate(double price) const = 0;
};

class DomesticTax : public TaxStrategy {
public:
    double calculate(double price) const override { return price * 0.13; }
};

class ForeignTax : public TaxStrategy {
public:
    double calculate(double price) const override { return price * 0.05; }
};

// 新增税率只需添加新子类, 无需修改已有代码
class LuxuryTax : public TaxStrategy {
public:
    double calculate(double price) const override { return price * 0.20; }
};

class TaxCalculator {
    const TaxStrategy* strategy_;
public:
    explicit TaxCalculator(const TaxStrategy* s) : strategy_(s) {}
    double calculate(double price) const { return strategy_->calculate(price); }
};

int main() {
    DomesticTax domestic;
    ForeignTax  foreign;
    LuxuryTax   luxury;

    std::cout << "国内税率: " << TaxCalculator(&domestic).calculate(100.0) << std::endl;
    std::cout << "国外税率: " << TaxCalculator(&foreign).calculate(100.0) << std::endl;
    std::cout << "奢侈税:   " << TaxCalculator(&luxury).calculate(100.0) << std::endl;
    return 0;
}
```

**运行输出：**
```
国内税率: 13
国外税率: 5
奢侈税:   20
```

### 示例3：Observer 模式——指针集合实现

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>

// Observer 模式: Subject 维护一个 Observer* 的集合
// 典型的"结构3: 组合指针"应用

class Observer {
public:
    virtual ~Observer() = default;
    virtual void update(const std::string& message) = 0;
};

class Subject {
    std::vector<Observer*> observers_;
public:
    void attach(Observer* obs) { observers_.push_back(obs); }
    void detach(Observer* obs) {
        observers_.erase(
            std::remove(observers_.begin(), observers_.end(), obs),
            observers_.end());
    }
    void notify(const std::string& msg) {
        for (auto* obs : observers_) obs->update(msg);
    }
};

class ConcreteObserverA : public Observer {
    std::string name_;
public:
    explicit ConcreteObserverA(const std::string& n) : name_(n) {}
    void update(const std::string& message) override {
        std::cout << "  [观察者A-" << name_ << "] 收到: " << message << std::endl;
    }
};

class ConcreteObserverB : public Observer {
    std::string name_;
public:
    explicit ConcreteObserverB(const std::string& n) : name_(n) {}
    void update(const std::string& message) override {
        std::cout << "  [观察者B-" << name_ << "] 收到: " << message << std::endl;
    }
};

int main() {
    Subject subject;
    ConcreteObserverA obs1("小明"), obs2("小红");
    ConcreteObserverB obs3("小刚");

    subject.attach(&obs1);
    subject.attach(&obs2);
    subject.attach(&obs3);

    subject.notify("系统即将维护");

    subject.detach(&obs2);
    subject.notify("维护已完成");
    return 0;
}
```

**运行输出：**
```
  [观察者A-小明] 收到: 系统即将维护
  [观察者A-小红] 收到: 系统即将维护
  [观察者B-小刚] 收到: 系统即将维护
  [观察者A-小明] 收到: 维护已完成
  [观察者B-小刚] 收到: 维护已完成
```

### 示例4：Decorator 模式——动态组合功能

```cpp
#include <iostream>
#include <string>
#include <memory>

class Component {
public:
    virtual ~Component() = default;
    virtual std::string operation() const = 0;
};

class ConcreteComponent : public Component {
public:
    std::string operation() const override { return "基础组件"; }
};

class Decorator : public Component {
protected:
    std::unique_ptr<Component> component_;
public:
    explicit Decorator(std::unique_ptr<Component> c)
        : component_(std::move(c)) {}
};

class ConcreteDecoratorA : public Decorator {
public:
    using Decorator::Decorator;
    std::string operation() const override {
        return "装饰A(" + component_->operation() + ")";
    }
};

class ConcreteDecoratorB : public Decorator {
public:
    using Decorator::Decorator;
    std::string operation() const override {
        return "装饰B(" + component_->operation() + ")";
    }
};

int main() {
    auto base = std::make_unique<ConcreteComponent>();
    std::cout << base->operation() << std::endl;

    auto a = std::make_unique<ConcreteDecoratorA>(std::move(base));
    std::cout << a->operation() << std::endl;

    auto b = std::make_unique<ConcreteDecoratorB>(std::move(a));
    std::cout << b->operation() << std::endl;
    return 0;
}
```

**运行输出：**
```
基础组件
装饰A(基础组件)
装饰B(装饰A(基础组件))
```

### 示例5：Template Method 模式——算法骨架与延迟步骤

```cpp
#include <iostream>
#include <string>

class DataParser {
public:
    virtual ~DataParser() = default;

    // 模板方法: 定义算法骨架, 不可重写
    void parse(const std::string& data) {
        std::cout << "  步骤1: 打开数据源" << std::endl;
        doParse(data);  // 延迟到子类实现
        std::cout << "  步骤3: 关闭数据源" << std::endl;
    }

protected:
    virtual void doParse(const std::string& data) = 0;
};

class JsonParser : public DataParser {
protected:
    void doParse(const std::string& data) override {
        std::cout << "  步骤2: 解析JSON -> " << data << std::endl;
    }
};

class XmlParser : public DataParser {
protected:
    void doParse(const std::string& data) override {
        std::cout << "  步骤2: 解析XML -> " << data << std::endl;
    }
};

int main() {
    JsonParser json;
    XmlParser  xml;

    std::cout << "JSON解析:" << std::endl;
    json.parse("{\"key\": \"value\"}");

    std::cout << "XML解析:" << std::endl;
    xml.parse("<root><key>value</key></root>");
    return 0;
}
```

**运行输出：**
```
JSON解析:
  步骤1: 打开数据源
  步骤2: 解析JSON -> {"key": "value"}
  步骤3: 关闭数据源
XML解析:
  步骤1: 打开数据源
  步骤2: 解析XML -> <root><key>value</key></root>
  步骤3: 关闭数据源
```
