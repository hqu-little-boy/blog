# 第23讲 命令模式（Command Pattern）

## 一、模式分类

命令模式（Command）与后面要讲的访问者模式（Visitor）被归为**行为变化模式**这一类别。

**行为变化模式的核心思想**：在软件构建过程中，组件行为的变化经常导致组件本身剧烈变化。行为（即一段代码）与对象之间的绑定关系极其紧密——本质上是一种天然的**编译式绑定**。

类的成员函数分为两类：
- **非虚函数 / 静态函数**：地址以编译式绑定的方式直接绑定
- **虚函数**：通过虚函数表指针以运行式绑定

这些绑定都是**紧耦合**的。行为变化模式的目标就是将组件的行为与组件本身进行**解耦**，从而支持组件行为的变化。

---

## 二、命令模式的定义与动机

### 问题场景

在软件构建过程中，行为的**请求者**（Invoker）和行为的**实现者**（Receiver）通常呈现紧耦合关系。但在某些场合下，我们需要对行为进行：
- **记录**（日志）
- **撤销/重做**（Undo/Redo）
- **事务处理**
- **排队/延迟执行**

在这种情况下，紧耦合的方式无法抵御变化，结果是不合适的。

### GoF 定义

> 将**请求封装为对象**，从而使得可以用不同的请求对客户进行参数化；对请求进行排队或记录日志，以及支持可撤销的操作。

**核心要点**：一旦将行为封装为对象（Object），就获得了极大的灵活性——对象可以当作参数传递、存储在字段中、序列化、存入数据结构（如栈、队列）等。

## 三、基本结构

### 类图结构

```
         ┌──────────────┐
         │   Command    │  ← 抽象命令接口
         │──────────────│
         │ + execute()  │
         └──────┬───────┘
                │
      ┌─────────┼─────────┐
      │                   │
┌─────┴──────┐   ┌───────┴──────┐
│ Concrete   │   │  Concrete    │
│ Command1   │   │  Command2    │
│────────────│   │──────────────│
│- state/arg │   │- state/arg   │
│+ execute() │   │+ execute()   │
└────────────┘   └──────────────┘
```

### 角色说明

| 角色 | 职责 |
|------|------|
| **Command** | 抽象命令接口，定义命令对象的接口规范（通常是 `execute()` 方法） |
| **ConcreteCommand** | 具体命令实现，封装了请求处理所需的参数和状态信息，调用 Receiver 的实际业务方法 |
| **Invoker** | 调用者，持有命令对象并触发执行 |
| **Receiver** | 接收者，实际执行业务逻辑的对象 |

### 宏命令（Macro Command）

可以使用**组合模式**（Composite Pattern）将多个命令组合成一个复合命令对象：

```cpp
class MacroCommand : public Command {
    std::vector<std::unique_ptr<Command>> commands_;
public:
    void addCommand(std::unique_ptr<Command> cmd) {
        commands_.push_back(std::move(cmd));
    }
    void execute() override {
        for (auto& cmd : commands_) {
            cmd->execute();  // 遍历执行所有子命令
        }
    }
};
```

## 四、示例代码

### 示例1：基本命令模式结构

以智能家居遥控器为例，展示命令模式的基本结构。

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <memory>

// 抽象命令接口
class Command {
public:
    virtual ~Command() = default;
    virtual void execute() = 0;
};

// 接收者：实际执行业务逻辑的对象
class Light {
public:
    void on()  { std::cout << "灯打开了" << std::endl; }
    void off() { std::cout << "灯关闭了" << std::endl; }
};

class Door {
public:
    void open()  { std::cout << "门打开了" << std::endl; }
    void close() { std::cout << "门关闭了" << std::endl; }
};

// 具体命令：开灯
class LightOnCommand : public Command {
    Light& light_;
public:
    explicit LightOnCommand(Light& light) : light_(light) {}
    void execute() override { light_.on(); }
};

// 具体命令：关灯
class LightOffCommand : public Command {
    Light& light_;
public:
    explicit LightOffCommand(Light& light) : light_(light) {}
    void execute() override { light_.off(); }
};

// 具体命令：开门
class DoorOpenCommand : public Command {
    Door& door_;
public:
    explicit DoorOpenCommand(Door& door) : door_(door) {}
    void execute() override { door_.open(); }
};

// 宏命令（组合命令）：将多个命令组合成一个
class MacroCommand : public Command {
    std::vector<std::unique_ptr<Command>> commands_;
public:
    void addCommand(std::unique_ptr<Command> cmd) {
        commands_.push_back(std::move(cmd));
    }
    void execute() override {
        for (auto& cmd : commands_) {
            cmd->execute();
        }
    }
};

// 调用者：持有命令对象并触发执行
class RemoteControl {
    std::vector<std::unique_ptr<Command>> history_;
public:
    void pressButton(std::unique_ptr<Command> cmd) {
        cmd->execute();
        history_.push_back(std::move(cmd));
    }
};

int main() {
    Light light;
    Door door;
    RemoteControl remote;

    std::cout << "--- 基本命令执行 ---" << std::endl;
    remote.pressButton(std::make_unique<LightOnCommand>(light));
    remote.pressButton(std::make_unique<DoorOpenCommand>(door));
    remote.pressButton(std::make_unique<LightOffCommand>(light));

    std::cout << "\n--- 宏命令执行 ---" << std::endl;
    auto macro = std::make_unique<MacroCommand>();
    macro->addCommand(std::make_unique<LightOnCommand>(light));
    macro->addCommand(std::make_unique<DoorOpenCommand>(door));
    remote.pressButton(std::move(macro));

    return 0;
}
```

**运行结果**：
```
--- 基本命令执行 ---
灯打开了
门打开了
灯关闭了

--- 宏命令执行 ---
灯打开了
门打开了
```

### 示例2：撤销/重做（Undo/Redo）

命令模式的经典应用——文本编辑器的撤销重做功能。命令接口增加 `undo()` 方法，每个具体命令同时实现执行和撤销逻辑。

```cpp
#include <iostream>
#include <string>
#include <stack>
#include <memory>

class Command {
public:
    virtual ~Command() = default;
    virtual void execute() = 0;
    virtual void undo() = 0;
};

// 接收者：文档
class Document {
    std::string content_;
public:
    void insert(int pos, const std::string& text) {
        content_.insert(pos, text);
    }
    std::string erase(int pos, int len) {
        std::string erased = content_.substr(pos, len);
        content_.erase(pos, len);
        return erased;
    }
    const std::string& content() const { return content_; }
};

// 具体命令：插入文本
class InsertCommand : public Command {
    Document& doc_;
    int pos_;
    std::string text_;
public:
    InsertCommand(Document& doc, int pos, std::string text)
        : doc_(doc), pos_(pos), text_(std::move(text)) {}
    void execute() override { doc_.insert(pos_, text_); }
    void undo() override    { doc_.erase(pos_, text_.size()); }
};

// 具体命令：删除文本
class EraseCommand : public Command {
    Document& doc_;
    int pos_;
    int len_;
    std::string erased_;  // 保存被删除的内容以支持 undo
public:
    EraseCommand(Document& doc, int pos, int len)
        : doc_(doc), pos_(pos), len_(len) {}
    void execute() override { erased_ = doc_.erase(pos_, len_); }
    void undo() override    { doc_.insert(pos_, erased_); }
};

// 调用者：编辑器
class Editor {
    Document& doc_;
    std::stack<std::unique_ptr<Command>> undoStack_;
    std::stack<std::unique_ptr<Command>> redoStack_;
public:
    explicit Editor(Document& doc) : doc_(doc) {}

    void executeCommand(std::unique_ptr<Command> cmd) {
        cmd->execute();
        undoStack_.push(std::move(cmd));
        while (!redoStack_.empty()) redoStack_.pop();
    }

    bool undo() {
        if (undoStack_.empty()) return false;
        auto cmd = std::move(undoStack_.top());
        undoStack_.pop();
        cmd->undo();
        redoStack_.push(std::move(cmd));
        return true;
    }

    bool redo() {
        if (redoStack_.empty()) return false;
        auto cmd = std::move(redoStack_.top());
        redoStack_.pop();
        cmd->execute();
        undoStack_.push(std::move(cmd));
        return true;
    }

    void printDoc() const {
        std::cout << "文档内容: \"" << doc_.content() << "\"" << std::endl;
    }
};

int main() {
    Document doc;
    Editor editor(doc);

    std::cout << "--- 编辑操作 ---" << std::endl;
    editor.executeCommand(std::make_unique<InsertCommand>(doc, 0, "Hello"));
    editor.printDoc();
    editor.executeCommand(std::make_unique<InsertCommand>(doc, 5, " World"));
    editor.printDoc();
    editor.executeCommand(std::make_unique<InsertCommand>(doc, 11, "!"));
    editor.printDoc();
    editor.executeCommand(std::make_unique<EraseCommand>(doc, 5, 6));
    editor.printDoc();

    std::cout << "\n--- 撤销操作 ---" << std::endl;
    editor.undo();
    editor.printDoc();
    editor.undo();
    editor.printDoc();

    std::cout << "\n--- 重做操作 ---" << std::endl;
    editor.redo();
    editor.printDoc();

    return 0;
}
```

**运行结果**：
```
--- 编辑操作 ---
文档内容: "Hello"
文档内容: "Hello World"
文档内容: "Hello World!"
文档内容: "Hello!"

--- 撤销操作 ---
文档内容: "Hello World!"
文档内容: "Hello World"

--- 重做操作 ---
文档内容: "Hello World!"
```

### 示例3：Command 模式 vs C++ 函数对象（仿函数）

```cpp
#include <iostream>
#include <vector>
#include <functional>
#include <memory>

// ====== Command 设计模式（运行时多态）======
class Command {
public:
    virtual ~Command() = default;
    virtual void execute() = 0;
};

class PrintHello : public Command {
public:
    void execute() override { std::cout << "Hello "; }
};

class PrintWorld : public Command {
public:
    void execute() override { std::cout << "World!" << std::endl; }
};

// ====== C++ 函数对象/仿函数（编译时多态）======
struct FunctorHello {
    void operator()() { std::cout << "Hello "; }
};

struct FunctorWorld {
    void operator()() { std::cout << "World!" << std::endl; }
};

template <typename Func>
void invoke(Func f) {
    f();  // 编译时绑定，无虚函数开销
}

int main() {
    // Command 模式
    std::cout << "=== Command 设计模式 ===" << std::endl;
    std::vector<std::unique_ptr<Command>> commands;
    commands.push_back(std::make_unique<PrintHello>());
    commands.push_back(std::make_unique<PrintWorld>());
    for (auto& cmd : commands) cmd->execute();

    // 函数对象
    std::cout << "\n=== C++ 函数对象 ===" << std::endl;
    std::vector<std::function<void()>> funcs;
    funcs.emplace_back(FunctorHello{});
    funcs.emplace_back(FunctorWorld{});
    for (auto& f : funcs) f();

    // Lambda
    std::cout << "\n=== Lambda 表达式 ===" << std::endl;
    std::vector<std::function<void()>> tasks;
    tasks.emplace_back([]{ std::cout << "Hello "; });
    tasks.emplace_back([]{ std::cout << "World!" << std::endl; });
    for (auto& task : tasks) task();

    return 0;
}
```

## 五、Command 模式 vs C++ 函数对象（仿函数）

这是本讲的重要对比内容。两者都将行为对象化，但有本质区别：

| 对比维度 | Command 设计模式 | C++ 函数对象（仿函数） |
|----------|------------------|------------------------|
| **接口规范** | 显式接口：函数名 `execute`、返回 `void`、无参数，规范严格 | 隐式接口：只要求函数签名（参数类型、返回值）一致，名称无所谓 |
| **绑定方式** | 运行时绑定（虚函数 → vtable） | 编译时绑定（模板 → 编译时多态） |
| **性能** | 有虚函数调用开销 | 无虚函数开销，性能更高 |
| **灵活性** | 接口规范固定 | 接口规范更灵活 |
| **典型实现** | 继承 + 虚函数重载 | `operator()` 重载 + 模板 |

### 关键历史背景

- GoF 定义 Command 模式大约在 **1994 年**
- C++ 泛型编程（STL）在 **1998 年** 左右才广泛发展
- 在设计模式被定义时，C++ 函数对象尚未广泛使用
- 后来 C++ 社区发现，函数对象在很多场景下可以替代 Command 模式

### C++ 中的实际应用现状

在 C++ 主流框架中，**函数对象的应用更广泛**。C++ 的设计哲学是**性能优先**，因此：
- Command 模式在 C++ 中的很多应用场景被**仿函数**（Function Object）替代
- 这与**迭代器模式**（Iterator）类似：STL 的泛型迭代器比 GoF 的 Iterator 模式更高效灵活
- 但这**不意味着** Command 模式没有价值——在 Java、C#、Swift 等语言中，Command 模式应用极其广泛

### 补充：现代 C++ 的 `std::function`

C++11 引入的 `std::function` 提供了一种类型擦除机制，可以统一存储各种可调用对象（函数指针、仿函数、lambda），在灵活性上接近 Command 模式，同时保留了较好的性能：

```cpp
#include <functional>
#include <vector>

// std::function 可以统一存储各种可调用对象
std::vector<std::function<void()>> tasks;
tasks.push_back([]{ /* lambda */ });
tasks.push_back(FunctorHello{});  // 仿函数
tasks.push_back(&someFunction);   // 函数指针

for (auto& t : tasks) t();  // 统一调用
```

## 六、设计模式与语言特性的关系

业界有一种观点：**设计模式是弥补语言设计不足而出现的**。

这个观点有其合理成分：
- 如果一门语言的设计足够充沛，框架类库足够丰富，某些设计模式就会变成语言特性的一部分
- 函数对象就是典型的例子——有人将其视为一种设计模式，但它已经成为 C++ 语言的基本机制
- 在 C++ 中，大多数情况下使用函数对象即可，不必刻意实现 Command 模式

**设计模式应结合具体语言来学习**，同一模式在不同语言中的实现方式和应用频率可能完全不同。

## 七、总结

| 要点 | 说明 |
|------|------|
| **核心思想** | 将请求（行为）封装为对象，使请求者与实现者解耦 |
| **关键优势** | 支持撤销/重做、命令排队、日志记录、宏命令组合 |
| **实现方式** | 抽象 Command 接口 + ConcreteCommand 具体实现 + Receiver 接收者 |
| **C++ 替代方案** | 函数对象（仿函数）+ 模板，编译时多态，性能更优 |
| **适用语言** | Java、C#、Swift 等语言中应用极为广泛 |
| **相关模式** | Composite（宏命令）、Memento（撤销状态保存）、Strategy |
