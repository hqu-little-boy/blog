# 设计模式简介

## 一、课程概述

侯捷老师的设计模式课程围绕三大核心部分展开：

1. **设计原则**：理解并掌握设计模式背后的一套设计原则，设计原则往往比具体的某个 Pattern 更为重要，因为它决定了 Pattern 的应用方式。
2. **设计模式**：以经典的 23 种设计模式为主干进行讲解。
3. **重构方法**：使用重构（Refactoring）作为应用设计模式的具体方法论。

---

## 二、什么是设计模式

### 2.1 模式的定义

> 每一个模式描述了一个在我们周围**不断重复发生的问题**，以及该问题的**解决方案的核心**。
> —— Christopher Alexander（建筑学家）

关键词：
- **不断重复**：问题是反复出现的。
- **解决方案**：提供可复用的解决方法。

因此我们可以反复使用该方案，而**不必重复劳动**——即"不需要重新发明轮子"。

### 2.2 经典著作：《设计模式：可复用面向对象软件的基础》

| 项目 | 内容 |
|------|------|
| 书名 | *Design Patterns: Elements of Reusable Object-Oriented Software* |
| 作者 | GoF 四人组（Erich Gamma、Richard Helm、Ralph Johnson、John Vlissides） |
| 出版年份 | 英文版 1994 年，中文版约 1998 年 |
| 模式数量 | 定义了 **23 种**经典设计模式 |

#### 副标题的重要性

本书副标题为"**可复用面向对象软件的基础**"，其中两个关键词：

- **可复用（Reusable）**：设计模式的**目标**。初学者容易忘记这个目标，导致南辕北辙。
- **面向对象（Object-Oriented）**：设计模式的**手法**，即具体的方法论。

#### 补充：GoF 四人组

GoF 是 "Gang of Four" 的缩写，指本书的四位作者。该书确立了设计模式在软件设计领域的地位，因此当我们口头说"设计模式"时，通常指的就是**面向对象的设计模式**。

### 2.3 设计模式的发展

当今模式领域已不仅限于面向对象设计模式，还包括：
- **架构模式**（Architectural Patterns）
- **数据库设计模式**
- **并发模式**等

但本书描述的 23 种模式依然是**经典中的经典**，至今仍位居各大计算机图书排行榜前列。

## 三、面向对象的两层思维模型

面向对象编程隐含着两层思维模式，这是理解设计模式的重要基础。

### 3.1 底层思维（向下）

**定义**：偏向机器层面的微观构造理解，帮助建立良好的**机器模型**。

核心内容：
- **语言构造**：类、对象、指针、引用等语法机制
- **编译转换**：编译器在编译代码时进行的大量底层工作（plumbing）
- **内存模型**：程序运行时对象在内存中的布局与管理
- **运行时机制**：异常处理（Exception Handling）、垃圾收集器（GC）等

### 3.2 抽象思维（向上）

**定义**：将现实世界抽象为程序代码的思维层次，帮助管理**代码复杂度**。

核心内容：
- **面向对象**：封装、继承、多态的抽象设计意义
- **组件封装**：模块化设计
- **设计模式**：可复用的解决方案
- **架构模式**：系统级的结构设计

### 3.3 两种思维的关系

- 光有底层思维是不够的——代码可能出错或性能不佳。
- 光有抽象思维也不够——不理解底层会导致实现层面的问题。
- **两种思维需要并重**，但设计模式课程更偏重于抽象思维。

## 四、软件领域的复杂性

### 4.1 根本原因：变化

> 建筑商从来不会给盖好一百层楼的大厦加一个地下室，但软件领域经常面临这种需求变更的冲击。
> —— Grady Booch（面向对象领域大师，《面向对象分析与设计》）

软件领域的**变化**来源：
- **客户需求**变化：从按年发布 → 按季度 → 按周 → 按天发布
- **技术平台**变化：每年都有新技术引入
- **开发团队**变化
- **市场环境**变化

### 4.2 应对复杂性的两种思维模型

#### 4.2.1 分解（Decomposition）

- 又称"**分而治之**"
- 将大问题拆分为小问题，将复杂流程拆分为子流程
- 以 C 语言为代表的结构化编程方法
- **优点**：直觉、有效
- **局限**：仅用分解在某些场景下不够，复用性差

#### 4.2.2 抽象（Abstraction）

- 由于不能掌握全部复杂对象，选择**忽略非本质的细节**，处理泛化或理想化后的对象模型
- 通过建立抽象层次，实现**统一处理**
- **优点**：复用性高，能够有效管理代码复杂度

## 五、代码对比：分解 vs 抽象

以一个简单的**画图工具**为例，对比两种设计方法。当需求从"画直线、画矩形"变更为"新增画圆形"时，观察两种方法的表现差异。

### 5.1 分解方式（Decomposition）

**设计思路**：针对每种图形分别维护数据结构和处理逻辑，分而治之。

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <cmath>

// ---- 基础数据结构 ----
struct Point {
    int x, y;
    Point(int x = 0, int y = 0) : x(x), y(y) {}
};

struct Line {
    Point start, end;
    Line(Point s, Point e) : start(s), end(e) {}
};

struct Rectangle {
    Point leftTop;
    int width, height;
    Rectangle(Point lt, int w, int h) : leftTop(lt), width(w), height(h) {}
};

struct Circle {
    Point center;
    int radius;
    Circle(Point c, int r) : center(c), radius(r) {}
};

// ---- 模拟绘图工具 ----
class Graphics {
public:
    void drawLine(int x1, int y1, int x2, int y2) {
        std::cout << "  画直线: (" << x1 << "," << y1
                  << ") -> (" << x2 << "," << y2 << ")" << std::endl;
    }
    void drawRectangle(int x, int y, int w, int h) {
        std::cout << "  画矩形: 左上角(" << x << "," << y
                  << ") 宽=" << w << " 高=" << h << std::endl;
    }
    void drawCircle(int cx, int cy, int r) {
        std::cout << "  画圆形: 圆心(" << cx << "," << cy
                  << ") 半径=" << r << std::endl;
    }
};

// ---- 窗口表单 (分解方式) ----
class MainForm {
private:
    Point p1, p2;
    // 每种图形分别维护一个容器 (分而治之)
    std::vector<Line> lineVector;
    std::vector<Rectangle> rectangleVector;
    std::vector<Circle> circleVector;  // 需求变更后新增

public:
    void onMouseDown(int x, int y) { p1 = Point(x, y); }
    void onMouseUp(int x, int y)   { p2 = Point(x, y); }

    void onMouseUpWithType(int x, int y, const std::string& type) {
        onMouseUp(x, y);
        if (type == "line") {
            lineVector.push_back(Line(p1, p2));
        } else if (type == "rectangle") {
            int w = p2.x - p1.x, h = p2.y - p1.y;
            rectangleVector.push_back(Rectangle(p1, w, h));
        } else if (type == "circle") {  // 需求变更: 新增分支
            int dx = p2.x - p1.x, dy = p2.y - p1.y;
            int radius = static_cast<int>(std::sqrt(dx*dx + dy*dy));
            circleVector.push_back(Circle(p1, radius));
        }
    }

    void onPaint() {
        Graphics g;
        // 分而治之: 针对每种图形分别绘制
        for (size_t i = 0; i < lineVector.size(); ++i)
            g.drawLine(lineVector[i].start.x, lineVector[i].start.y,
                       lineVector[i].end.x, lineVector[i].end.y);
        for (size_t i = 0; i < rectangleVector.size(); ++i)
            g.drawRectangle(rectangleVector[i].leftTop.x,
                            rectangleVector[i].leftTop.y,
                            rectangleVector[i].width,
                            rectangleVector[i].height);
        for (size_t i = 0; i < circleVector.size(); ++i)  // 需求变更: 新增循环
            g.drawCircle(circleVector[i].center.x,
                         circleVector[i].center.y,
                         circleVector[i].radius);
    }
};
```

**需求变更时的改动点（新增圆形）**：

| 改动位置 | 改动内容 |
|----------|----------|
| ① 类型定义 | 新增 `Circle` 结构体 |
| ② `MainForm` 成员 | 新增 `circleVector` 容器 |
| ③ `onMouseUpWithType` | 新增 `circle` 分支 |
| ④ `onPaint` | 新增 circle 绘制循环 |

> **问题**：改动点分散在多处，复用性差。大型工程中这种模式会导致"改一处牵一发而动全身"。

### 5.2 抽象方式（Abstraction）

**设计思路**：定义抽象基类 `Shape`，各图形类继承并实现自己的 `draw` 方法，统一通过多态调用。

```cpp
#include <iostream>
#include <vector>
#include <cmath>

// ---- 基础数据结构 ----
struct Point {
    int x, y;
    Point(int x = 0, int y = 0) : x(x), y(y) {}
};

// ---- 模拟绘图工具 ----
class Graphics {
public:
    void drawLine(int x1, int y1, int x2, int y2) {
        std::cout << "  画直线: (" << x1 << "," << y1
                  << ") -> (" << x2 << "," << y2 << ")" << std::endl;
    }
    void drawRectangle(int x, int y, int w, int h) {
        std::cout << "  画矩形: 左上角(" << x << "," << y
                  << ") 宽=" << w << " 高=" << h << std::endl;
    }
    void drawCircle(int cx, int cy, int r) {
        std::cout << "  画圆形: 圆心(" << cx << "," << cy
                  << ") 半径=" << r << std::endl;
    }
};

// =============================================
// 抽象基类 Shape (抽象思维的核心)
// =============================================
class Shape {
public:
    virtual void draw(Graphics& g) = 0;  // 纯虚函数
    virtual ~Shape() {}                   // 虚析构函数
};

class Line : public Shape {
    Point start, end;
public:
    Line(Point s, Point e) : start(s), end(e) {}
    void draw(Graphics& g) override {
        g.drawLine(start.x, start.y, end.x, end.y);
    }
};

class Rectangle : public Shape {
    Point leftTop;
    int width, height;
public:
    Rectangle(Point lt, int w, int h) : leftTop(lt), width(w), height(h) {}
    void draw(Graphics& g) override {
        g.drawRectangle(leftTop.x, leftTop.y, width, height);
    }
};

class Circle : public Shape {  // 需求变更: 新增类
    Point center;
    int radius;
public:
    Circle(Point c, int r) : center(c), radius(r) {}
    void draw(Graphics& g) override {
        g.drawCircle(center.x, center.y, radius);
    }
};

// ---- 窗口表单 (抽象方式) ----
class MainForm {
private:
    Point p1, p2;
    std::vector<Shape*> shapeVector;  // 统一容器，存储多态指针

public:
    ~MainForm() {
        for (size_t i = 0; i < shapeVector.size(); ++i)
            delete shapeVector[i];
    }

    void onMouseDown(int x, int y) { p1 = Point(x, y); }
    void onMouseUp(int x, int y)   { p2 = Point(x, y); }

    void onMouseUpWithType(int x, int y, const std::string& type) {
        onMouseUp(x, y);
        Shape* pShape = nullptr;
        if (type == "line") {
            pShape = new Line(p1, p2);
        } else if (type == "rectangle") {
            int w = p2.x - p1.x, h = p2.y - p1.y;
            pShape = new Rectangle(p1, w, h);
        } else if (type == "circle") {  // 需求变更: 新增分支
            int dx = p2.x - p1.x, dy = p2.y - p1.y;
            int radius = static_cast<int>(std::sqrt(dx*dx + dy*dy));
            pShape = new Circle(p1, radius);
        }
        if (pShape) shapeVector.push_back(pShape);
    }

    void onPaint() {
        Graphics g;
        // 统一处理: 多态调用，各司其职
        for (size_t i = 0; i < shapeVector.size(); ++i)
            shapeVector[i]->draw(g);  // 多态调用
    }
};
```

**需求变更时的改动点（新增圆形）**：

| 改动位置 | 改动内容 |
|----------|----------|
| ① 新增类型 | 新增 `Circle` 类（继承 `Shape`，实现 `draw`） |
| ② `onMouseUpWithType` | 新增 `circle` 创建逻辑 |
| ~~③ onPaint~~ | **无需修改** |

> **优势**：核心处理逻辑（`onPaint`）无需变动，新增类型只需扩展，符合**开闭原则**（对扩展开放，对修改关闭）。

## 六、核心概念对比

### 6.1 分解 vs 抽象

| 维度 | 分解（Decomposition） | 抽象（Abstraction） |
|------|----------------------|---------------------|
| 思维方式 | 分而治之，针对每种类型分别处理 | 建立抽象层次，统一处理 |
| 代码特征 | 多个 `if-else` / 多个容器 | 继承体系 + 虚函数 + 多态 |
| 需求变更 | 改动点多，牵一发而动全身 | 改动点少，核心逻辑不变 |
| 复用性 | **差** | **高** |
| 设计评判 | 不是好的面向对象设计 | 好的面向对象设计 |

### 6.2 关键术语

| 术语 | 说明 |
|------|------|
| **纯虚函数** | 没有实现的虚函数（`= 0`），使类成为抽象类 |
| **虚析构函数** | 确保通过基类指针删除子类对象时，子类析构函数被正确调用 |
| **多态调用** | 根据对象的实际类型调用对应的方法（"各司其职"） |
| **对象切割** | 将子类对象赋值给基类对象时，子类特有部分被丢弃；因此需要使用**指针**来存储多态对象 |
| **开闭原则** | 对扩展开放，对修改关闭（Open-Closed Principle, OCP） |

### 6.3 为什么用指针存储 Shape 对象

在抽象方式中，`shapeVector` 存储的是 `Shape*` 指针而非 `Shape` 对象，原因如下：

```cpp
// 错误：会导致对象切割
std::vector<Shape> shapeVector;
shapeVector.push_back(Line(Point(0,0), Point(100,100)));  // Line 被切割为 Shape

// 正确：使用指针支持多态
std::vector<Shape*> shapeVector;
shapeVector.push_back(new Line(Point(0,0), Point(100,100)));  // 多态保留
```

使用指针后，`shapeVector[i]->draw(g)` 能够根据实际存储的类型（`Line`、`Rectangle`、`Circle`）调用对应的 `draw` 实现，这就是**多态调用**。

## 七、设计模式的核心目标

### 7.1 复用性（Reusability）

> 软件设计的金科玉律就是**复用性**。

- 具有极高的复用性，你的软件设计才是好的设计。
- 所有设计模式的目标都是**复用性**。
- 评判标准：当需求变化时，改动越少，复用性越高。

### 7.2 抽象的力量

- 抽象使得我们能用一种**通用的方法统一处理**各种具体类型。
- 抽象能够使得已有的处理方法**不变**（复用），只在新增类型时做少量扩展。
- 设计模式本质上都是围绕"**抽象**"这个关键词进行的各种变化。

## 八、面向对象的深入理解

### 8.1 向下：理解内部机制

- **封装**：数据成员（DataMember）+ 函数成员（FunctionMember）的封装
- **继承**：子类与父类的对象模型、内存布局
- **多态**：虚函数表（vtable）、虚函数表指针（vptr）在动态绑定中的作用

### 8.2 向上：把握设计意义

- 使用了封装、继承、多态的机制，**并不意味着**你的设计就是好的面向对象设计。
- 评判设计的标准要靠**抽象思维**——即如何用这些机制来表达现实世界。
- 掌握**什么是好的面向对象设计**比掌握语言机制本身更重要。
