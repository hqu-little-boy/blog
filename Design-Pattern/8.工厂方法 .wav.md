# 工厂方法模式 (Factory Method Pattern)

> 侯捷 C++ 设计模式 第8讲 笔记

---

## 一、模式分类

工厂方法模式属于**对象创建型模式**。

对象创建模式的核心思想：绕开以 `new` 为代表的传统对象创建方式，避免对象创建过程中导致的**紧耦合**（依赖具体类），从而支持对象创建的稳定性。

> 对象创建模式是**接口抽象之后的第一步工作**。面向接口编程不能只管等号左边（变量声明为抽象类），还要管等号右边（`new` 出来的对象）。

C++ 中共有四种对象创建型模式，它们解决的是**同一个问题**（绕开 `new` 带来的紧耦合），只是在不同演化阶段的细节有所区别：

1. **工厂方法** (Factory Method)
2. **抽象工厂** (Abstract Factory)
3. **原型模式** (Prototype)
4. **构造器模式** (Builder)

## 二、问题引入：文件分割器

### 2.1 初始设计 (MainForm1 — 反面示例)

```cpp
class MainForm {
public:
    void onButtonClick() {
        // 直接依赖具体类 BinarySplitter
        ISplitter* splitter = new BinarySplitter();
        splitter->split();
        delete splitter;
    }
};
```

**问题分析：**

- 第14行 `ISplitter* splitter` — 声明为抽象类（面向接口编程）
- 第15行 `new BinarySplitter()` — 依赖具体类（违反依赖倒置原则）

虽然变量声明为抽象类型，但 `new` 的对象仍然是具体类型。只要代码中**有一处**依赖具体类，就打破了依赖倒置原则（DIP），编译时仍然需要 `BinarySplitter` 存在。

### 2.2 依赖倒置原则 (DIP)

> **依赖倒置原则**：应该依赖抽象，不应该依赖实现细节。

这里的"依赖"指的是**编译时依赖**——编译时需要某个类存在才能编译通过。

```
MainForm  ──编译时依赖──>  BinarySplitter (具体类)  ✗ 违反 DIP
```

## 三、解决方案的推导过程

### 3.1 尝试一：直接 new 抽象类

```cpp
ISplitter* splitter = new ISplitter();  // ✗ 抽象类不能实例化
```

抽象类/接口无法直接创建对象，此路不通。

### 3.2 尝试二：用普通方法返回对象

```cpp
ISplitter* createSplitter() {
    return new BinarySplitter();  // 仍然依赖具体类
}
```

只是把 `new` 搬到了一个函数里，没有根本解决依赖问题。

### 3.3 尝试三：用工厂类封装

```cpp
class SplitterFactory {
public:
    ISplitter* createSplitter() {
        return new BinarySplitter();
    }
};
```

```
MainForm ──> SplitterFactory ──> BinarySplitter
```

`MainForm` 依赖 `SplitterFactory`，而 `SplitterFactory` 依赖 `BinarySplitter`。间接依赖仍然是编译时依赖，问题依然存在。

### 3.4 最终方案：虚函数实现"多态的 new"

关键洞察：**虚函数是运行时依赖**，可以将编译时依赖延迟到运行时。

```cpp
class SplitterFactory {
public:
    virtual ISplitter* createSplitter() = 0;  // 工厂方法
    virtual ~SplitterFactory() = default;
};
```

通过虚函数，对象的创建被**延迟到子类**。`MainForm` 只依赖抽象的 `SplitterFactory` 和 `ISplitter`，不再依赖任何具体类。

## 四、工厂方法模式的完整结构

### 4.1 类图结构

```
│  - factory   │          │ + createSplitter()│  ← 工厂方法 (虚函数)
│  + onClick() │          │   [= 0]           │

        │                 ┌────────┼────────┬──────────┐
        │                 │        │        │          │

   │ ISplitter│    │ Binary  │ │ Txt  │ │Picture│ │ Video │
   │ (产品)   │    │ Splitter│ │Split-│ │Split- │ │Split- │
   │          │    │ Factory │ │ter   │ │ter    │ │ter    │
   │ + split()│    │         │ │Factory│ │Factory│ │Factory│
   │  [= 0]   │    └────┬────┘ └──┬───┘ └───┬───┘ └───┬───┘
   └────┬─────┘         │        │         │         │
        │               ▼        ▼         ▼         ▼
   ┌────┼────┬────────┐
   ▼    ▼    ▼        ▼
 Binary Txt Picture Video
 Splitter Splitter Splitter Splitter
 (具体产品 / ConcreteProduct)
```

### 4.2 各角色对应关系

| 类图角色 | 代码对应 |
|---------|---------|
| **Product** (抽象产品) | `ISplitter` — 抽象分割器基类 |
| **ConcreteProduct** (具体产品) | `BinarySplitter`, `TxtSplitter`, `PictureSplitter`, `VideoSplitter` |
| **Creator** (抽象工厂) | `SplitterFactory` — 含虚函数 `createSplitter()` |
| **ConcreteCreator** (具体工厂) | `BinarySplitterFactory`, `TxtSplitterFactory` 等 |

### 4.3 稳定与变化的分离

```
红色 (稳定)                    蓝色 (变化)
┌──────────────────┐          ┌─────────────────────────────┐
│  ISplitter       │          │  BinarySplitter             │
│  SplitterFactory │          │  TxtSplitter                │
│  MainForm        │          │  PictureSplitter            │
│                  │          │  VideoSplitter              │
│  (只依赖这些)     │          │  BinarySplitterFactory      │
│                  │          │  TxtSplitterFactory         │
│                  │          │  PictureSplitterFactory     │
│                  │          │  VideoSplitterFactory       │
└──────────────────┘          └─────────────────────────────┘
```

`MainForm` **只依赖红色部分**（抽象类），**不依赖蓝色部分**（具体类）。变化被"关进笼子"——隔离到创建 `MainForm` 的局部代码中。

## 五、模式定义

> **工厂方法模式**：定义一个用于创建对象的接口，让子类决定实例化哪个类。该模式使得一个类的实例化**延迟到子类**（目的：**解耦**，手段：**虚函数**）。

三个关键词：
- **接口** — `virtual ISplitter* createSplitter() = 0`
- **子类决定** — `BinarySplitterFactory` 决定创建 `BinarySplitter`
- **延迟** — 创建动作不在编译时确定，而在运行时通过多态调用

## 六、核心设计思想

### 6.1 "多态的 new"

C++ 语言本身没有提供多态的 `new`，但通过虚函数可以**创造性地**实现多态的 `new`：

```cpp
// 调用的是虚函数, 运行时决定创建哪个具体类
ISplitter* splitter = factory->createSplitter();
```

### 6.2 变化的"笼子"

> 面向对象的松耦合设计，并不是把变化消灭掉了，而是把变化**赶到某一个局部的地方**。

- **MainForm1 (反面)**：变化在代码中到处跳——所有需要 `new BinarySplitter` 的地方都产生耦合
- **MainForm2 (正面)**：变化被隔离到 `MainForm` 外部（构造时传入工厂），`MainForm` 内部稳坐泰山

### 6.3 扩展而非更改

- **需求变化时**：不需要修改 `MainForm` 的代码（扩展策略）
- 只需要：添加新的具体产品类 + 对应的具体工厂类，然后将工厂传入 `MainForm`

```cpp
// 需求变化: 要支持视频分割
// 不改 MainForm, 只需新增:
class VideoSplitter : public ISplitter { ... };
class VideoSplitterFactory : public SplitterFactory { ... };

// 使用时传入新工厂即可
VideoSplitterFactory videoFactory;
MainForm form(&videoFactory);  // MainForm 代码不变
```

## 七、完整示例代码

### 7.1 经典版本

```cpp
#include <iostream>
#include <string>

// ========== 抽象产品 ==========
class ISplitter {
public:
    virtual void split() = 0;
    virtual ~ISplitter() = default;
};

// ========== 具体产品 ==========
class BinarySplitter : public ISplitter {
public:
    void split() override {
        std::cout << "[BinarySplitter] 以二进制方式分割文件" << std::endl;
    }
};

class TxtSplitter : public ISplitter {
public:
    void split() override {
        std::cout << "[TxtSplitter] 按行分割文本文件" << std::endl;
    }
};

class PictureSplitter : public ISplitter {
public:
    void split() override {
        std::cout << "[PictureSplitter] 按像素块分割图片文件" << std::endl;
    }
};

class VideoSplitter : public ISplitter {
public:
    void split() override {
        std::cout << "[VideoSplitter] 按关键帧分割视频文件" << std::endl;
    }
};

// ========== 抽象工厂 ==========
class SplitterFactory {
public:
    virtual ISplitter* createSplitter() = 0;
    virtual ~SplitterFactory() = default;
};

// ========== 具体工厂 ==========
class BinarySplitterFactory : public SplitterFactory {
public:
    ISplitter* createSplitter() override {
        return new BinarySplitter();
    }
};

class TxtSplitterFactory : public SplitterFactory {
public:
    ISplitter* createSplitter() override {
        return new TxtSplitter();
    }
};

class PictureSplitterFactory : public SplitterFactory {
public:
    ISplitter* createSplitter() override {
        return new PictureSplitter();
    }
};

class VideoSplitterFactory : public SplitterFactory {
public:
    ISplitter* createSplitter() override {
        return new VideoSplitter();
    }
};

// ========== 使用者: 只依赖抽象 ==========
class MainForm {
private:
    SplitterFactory* factory;

public:
    MainForm(SplitterFactory* f) : factory(f) {}

    void onButtonClick() {
        ISplitter* splitter = factory->createSplitter();
        splitter->split();
        delete splitter;
    }
};

int main() {
    BinarySplitterFactory binaryFactory;
    MainForm form(&binaryFactory);
    form.onButtonClick();  // 输出: [BinarySplitter] 以二进制方式分割文件

    VideoSplitterFactory videoFactory;
    MainForm form2(&videoFactory);
    form2.onButtonClick();  // 输出: [VideoSplitter] 按关键帧分割视频文件

    return 0;
}
```

### 7.2 现代 C++ 版本（智能指针）

```cpp
#include <iostream>
#include <memory>
#include <vector>

// ========== 抽象产品 ==========
class Shape {
public:
    virtual void draw() const = 0;
    virtual double area() const = 0;
    virtual ~Shape() = default;
};

// ========== 具体产品 ==========
class Circle : public Shape {
    double radius_;
public:
    explicit Circle(double r) : radius_(r) {}
    void draw() const override {
        std::cout << "Circle(r=" << radius_ << ")" << std::endl;
    }
    double area() const override { return 3.14159265 * radius_ * radius_; }
};

class Rectangle : public Shape {
    double w_, h_;
public:
    Rectangle(double w, double h) : w_(w), h_(h) {}
    void draw() const override {
        std::cout << "Rectangle(" << w_ << " x " << h_ << ")" << std::endl;
    }
    double area() const override { return w_ * h_; }
};

class Triangle : public Shape {
    double base_, height_;
public:
    Triangle(double b, double h) : base_(b), height_(h) {}
    void draw() const override {
        std::cout << "Triangle(base=" << base_ << ", h=" << height_ << ")" << std::endl;
    }
    double area() const override { return 0.5 * base_ * height_; }
};

// ========== 抽象工厂 ==========
class ShapeFactory {
public:
    virtual std::unique_ptr<Shape> createShape() const = 0;
    virtual ~ShapeFactory() = default;
};

// ========== 具体工厂 (支持带参数构造) ==========
class CircleFactory : public ShapeFactory {
    double radius_;
public:
    explicit CircleFactory(double r) : radius_(r) {}
    std::unique_ptr<Shape> createShape() const override {
        return std::make_unique<Circle>(radius_);
    }
};

class RectangleFactory : public ShapeFactory {
    double w_, h_;
public:
    RectangleFactory(double w, double h) : w_(w), h_(h) {}
    std::unique_ptr<Shape> createShape() const override {
        return std::make_unique<Rectangle>(w_, h_);
    }
};

// ========== 使用者 ==========
class Canvas {
public:
    void render(const ShapeFactory& factory) const {
        auto shape = factory.createShape();
        shape->draw();
        std::cout << "  面积 = " << shape->area() << std::endl;
    }
};

int main() {
    Canvas canvas;
    CircleFactory circleFactory(5.0);
    RectangleFactory rectFactory(4.0, 6.0);

    canvas.render(circleFactory);
    canvas.render(rectFactory);

    return 0;
}
```

## 八、工厂方法模式的优缺点

### 优点

| 优点 | 说明 |
|-----|------|
| **解耦** | 使用者（`MainForm`）不依赖具体类，只依赖抽象接口 |
| **符合开闭原则** | 新增产品只需新增具体产品类 + 具体工厂类，无需修改已有代码 |
| **符合依赖倒置原则** | 高层模块依赖抽象，不依赖具体实现 |
| **支持扩展** | 扩展而非更改的策略 |

### 缺点

| 缺点 | 说明 |
|-----|------|
| **类的数量膨胀** | 每增加一个产品，就需要增加一个对应的工厂类 |
| **参数一致性要求** | 所有工厂的创建方法参数必须相同；若各产品创建参数不同，工厂方法模式不再适用 |
| **内存管理** | 原始版本需手动管理内存（`delete`），建议使用智能指针 |

---

## 九、与其他模式的关系

| 模式 | 区别 |
|-----|------|
| **抽象工厂** | 工厂方法针对**单个产品**的变化；抽象工厂针对**一族产品**的变化 |
| **原型模式** | 通过克隆（`clone`）而非 `new` 来创建对象，避免工厂类数量膨胀 |
| **单例模式** | 确保一个类只有一个实例，工厂方法可以与单例结合使用 |

---

## 十、适用场景

- 当一个类不知道它所需要的对象的具体类型时
- 当一个类希望由其子类来指定所创建的对象时
- 当需要将对象的创建与使用分离，以实现解耦时
- 当面临**单个对象**的需求经常变化的场景时

## 十一、内存管理注意事项

课堂示例中为简化演示，未处理内存管理。实际使用中应注意：

```cpp
// 方式一: 使用后手动 delete
ISplitter* splitter = factory->createSplitter();
splitter->split();
delete splitter;

// 方式二 (推荐): 使用智能指针自动管理
std::unique_ptr<ISplitter> splitter(factory->createSplitter());
splitter->split();
// 离开作用域自动释放

// 方式三: 工厂中提供 release 方法
class SplitterFactory {
public:
    virtual ISplitter* createSplitter() = 0;
    virtual void releaseSplitter(ISplitter* p) { delete p; }
    virtual ~SplitterFactory() = default;
};
```

## 十二、要点总结

1. **核心目标**：绕开 `new` 带来的紧耦合，将对象创建延迟到子类
2. **关键手段**：虚函数（运行时多态），实现"多态的 `new`"
3. **设计原则**：依赖倒置原则（DIP）、开闭原则（OCP）
4. **变化隔离**：不是消灭变化，而是把变化赶到局部（"关进笼子"）
5. **扩展策略**：需求变化时，添加新类而非修改已有代码
6. **适用范围**：单个对象的需求变化；各产品的创建参数需一致
