# 代理模式（Proxy Pattern）

## 一、模式定义

> 为其他对象提供一种**代理**以控制对这个对象的访问。
> —— 《设计模式：可复用面向对象软件的基础》

代理模式的核心思想是：**增加一层间接层**，在不改变接口的前提下，对真实对象的访问进行控制和增强，同时对客户端保持**透明性**。

---

## 二、解决的问题

在面向对象系统中，直接使用某些对象可能会带来以下问题：

| 问题类型 | 说明 |
|---------|------|
| **创建开销大** | 对象的构造和初始化代价高昂（如大图片加载、数据库连接） |
| **安全控制** | 需要在访问前进行权限校验 |
| **分布式访问** | 对象位于远程进程或远程机器，无法直接访问 |
| **性能优化** | 需要延迟加载、缓存、写时复制等优化手段 |

代理模式通过引入一个**代理对象**（Proxy），在客户端与真实对象之间建立间接层，从而在不失去接口一致性的前提下，实现上述额外功能。

---

## 三、模式结构

```
        ┌─────────────────┐
        │    <<interface>> │
        │     ISubject     │
        │─────────────────│
        │ + request()      │
        └────────┬────────┘
                 │
        ┌────────┴────────┐
        │                 │
  ┌─────┴──────┐   ┌──────┴───────┐
  │ RealSubject │   │    Proxy      │
  │─────────────│   │──────────────│
  │ + request() │   │ - realSubject │
  └─────────────┘   │ + request()  │
                    └──────────────┘
```

**核心角色：**

| 角色 | 职责 |
|------|------|
| **ISubject（抽象主题）** | 定义 RealSubject 和 Proxy 的公共接口 |
| **RealSubject（真实主题）** | 定义 Proxy 所代表的真实对象 |
| **Proxy（代理）** | 持有 RealSubject 的引用，提供与 RealSubject 相同的接口，可在调用前后附加额外操作 |

**客户端（Client）** 通过 ISubject 接口访问对象，不感知是否使用了代理。

---

## 四、典型应用场景

### 4.1 虚拟代理（Virtual Proxy）—— 延迟加载

当对象的创建开销很大时，虚拟代理延迟对象的创建，直到真正需要使用时才实例化。

**典型场景：** 图片加载、大文件读取、数据库连接池。

### 4.2 保护代理（Protection Proxy）—— 权限控制

在调用真实对象之前进行权限检查，决定是否允许访问。

**典型场景：** 文件系统权限、API 访问控制、角色鉴权。

### 4.3 远程代理（Remote Proxy）—— 分布式访问

为远程对象在本地创建一个代理，客户端通过代理与远程对象通信。代理负责处理网络通信的细节（序列化、反序列化、协议封装等）。

**典型场景：**
- gRPC / Protobuf 自动生成的 Stub 类
- REST API 的客户端 SDK
- CORBA、Java RMI 等分布式中间件

### 4.4 写时复制代理（Copy-on-Write）—— 性能优化

对象在复制时仅进行**浅拷贝**（共享数据），只有在真正需要修改时才进行**深拷贝**。这是一种对性能的特殊优化。

**典型场景：** 字符串类的实现（如早期 C++ 标准库的 `std::string` 实现）、容器类的延迟拷贝。

> **注意：** C++11 之后标准库的 `std::string` 已不再使用 COW（因为移动语义提供了更好的优化），但 COW 作为一种设计思想仍然有价值。

## 五、示例代码

### 5.1 基本代理模式结构

```cpp
#include <iostream>
#include <string>
#include <memory>

// Subject 接口
class ISubject {
public:
    virtual ~ISubject() = default;
    virtual void request() const = 0;
};

// RealSubject：真正的主体对象
class RealSubject : public ISubject {
public:
    void request() const override {
        std::cout << "RealSubject: 处理请求" << std::endl;
    }
};

// Proxy：代理类，持有 RealSubject 的引用
class Proxy : public ISubject {
private:
    std::unique_ptr<RealSubject> realSubject_;

    bool checkAccess() const {
        std::cout << "Proxy: 检查访问权限" << std::endl;
        return true;
    }

    void logAccess() const {
        std::cout << "Proxy: 记录访问日志" << std::endl;
    }

public:
    Proxy(std::unique_ptr<RealSubject> realSubject)
        : realSubject_(std::move(realSubject)) {}

    void request() const override {
        if (checkAccess()) {
            realSubject_->request();
            logAccess();
        }
    }
};

// Client
int main() {
    std::cout << "=== 直接访问 RealSubject ===" << std::endl;
    auto realSubject = std::make_unique<RealSubject>();
    realSubject->request();

    std::cout << "\n=== 通过 Proxy 访问 ===" << std::endl;
    auto proxy = std::make_unique<Proxy>(std::make_unique<RealSubject>());
    proxy->request();

    return 0;
}
```

**输出：**
```
=== 直接访问 RealSubject ===
RealSubject: 处理请求

=== 通过 Proxy 访问 ===
Proxy: 检查访问权限
RealSubject: 处理请求
Proxy: 记录访问日志
```

### 5.2 虚拟代理（延迟加载）

```cpp
#include <iostream>
#include <string>
#include <memory>

// Subject 接口
class IImage {
public:
    virtual ~IImage() = default;
    virtual void display() const = 0;
};

// RealSubject：高开销的真实对象
class HighResImage : public IImage {
private:
    std::string filename_;

public:
    explicit HighResImage(const std::string& filename) : filename_(filename) {
        std::cout << "HighResImage: 加载图片 '" << filename_
                  << "' (开销很大)" << std::endl;
    }

    void display() const override {
        std::cout << "HighResImage: 显示图片 '" << filename_ << "'" << std::endl;
    }
};

// Virtual Proxy：延迟初始化，直到真正需要时才创建对象
class ImageProxy : public IImage {
private:
    std::string filename_;
    mutable std::unique_ptr<HighResImage> realImage_;

public:
    explicit ImageProxy(const std::string& filename) : filename_(filename) {
        std::cout << "ImageProxy: 创建代理 (图片尚未加载)" << std::endl;
    }

    void display() const override {
        if (!realImage_) {
            std::cout << "ImageProxy: 首次访问，触发延迟加载..." << std::endl;
            realImage_ = std::make_unique<HighResImage>(filename_);
        }
        realImage_->display();
    }
};

int main() {
    std::cout << "=== 创建代理 ===" << std::endl;
    auto image = std::make_unique<ImageProxy>("photo_hd.png");

    std::cout << "\n=== 第一次显示 (触发加载) ===" << std::endl;
    image->display();

    std::cout << "\n=== 第二次显示 (已缓存，不再加载) ===" << std::endl;
    image->display();

    return 0;
}
```

**输出：**
```
=== 创建代理 ===
ImageProxy: 创建代理 (图片尚未加载)

=== 第一次显示 (触发加载) ===
ImageProxy: 首次访问，触发加载...
HighResImage: 加载图片 'photo_hd.png' (开销很大)
HighResImage: 显示图片 'photo_hd.png'

=== 第二次显示 (已缓存，不再加载) ===
HighResImage: 显示图片 'photo_hd.png'
```

### 5.3 保护代理（权限控制）

```cpp
#include <iostream>
#include <string>
#include <memory>

// Subject 接口
class IDocument {
public:
    virtual ~IDocument() = default;
    virtual void read() const = 0;
    virtual void write(const std::string& content) = 0;
};

// RealSubject：真实的文档对象
class RealDocument : public IDocument {
private:
    std::string content_;

public:
    explicit RealDocument(const std::string& content) : content_(content) {}

    void read() const override {
        std::cout << "文档内容: " << content_ << std::endl;
    }

    void write(const std::string& content) override {
        content_ = content;
        std::cout << "文档已更新" << std::endl;
    }
};

// Protective Proxy：权限控制代理
class ProtectedDocument : public IDocument {
private:
    std::unique_ptr<RealDocument> document_;
    std::string userRole_;

public:
    ProtectedDocument(std::unique_ptr<RealDocument> doc,
                      const std::string& role)
        : document_(std::move(doc)), userRole_(role) {}

    void read() const override {
        std::cout << "[安全检查] 用户角色: " << userRole_
                  << " -> 允许读取" << std::endl;
        document_->read();
    }

    void write(const std::string& content) override {
        if (userRole_ == "admin" || userRole_ == "editor") {
            std::cout << "[安全检查] 用户角色: " << userRole_
                      << " -> 允许写入" << std::endl;
            document_->write(content);
        } else {
            std::cout << "[安全检查] 用户角色: " << userRole_
                      << " -> 拒绝写入，权限不足!" << std::endl;
        }
    }
};

int main() {
    std::cout << "=== 管理员访问 ===" << std::endl;
    auto adminDoc = std::make_unique<ProtectedDocument>(
        std::make_unique<RealDocument>("机密文件"), "admin");
    adminDoc->read();
    adminDoc->write("更新后的机密文件");

    std::cout << "\n=== 普通用户访问 ===" << std::endl;
    auto guestDoc = std::make_unique<ProtectedDocument>(
        std::make_unique<RealDocument>("机密文件"), "guest");
    guestDoc->read();
    guestDoc->write("尝试修改");

    return 0;
}
```

**输出：**
```
=== 管理员访问 ===
[安全检查] 用户角色: admin -> 允许读取
文档内容: 机密文件
[安全检查] 用户角色: admin -> 允许写入
文档已更新

=== 普通用户访问 ===
[安全检查] 用户角色: guest -> 允许读取
文档内容: 机密文件
[安全检查] 用户角色: guest -> 拒绝写入，权限不足!
```

### 5.4 写时复制代理（Copy-on-Write）

```cpp
#include <iostream>
#include <string>
#include <memory>

class CowString {
private:
    struct StringData {
        std::string data;
        int refCount;
        explicit StringData(const std::string& s) : data(s), refCount(1) {}
    };

    StringData* pData_;

    void addRef() {
        if (pData_) ++pData_->refCount;
    }

    void release() {
        if (pData_ && --pData_->refCount == 0) {
            delete pData_;
            pData_ = nullptr;
        }
    }

    // 写时复制：引用计数 > 1 时深拷贝
    void detach() {
        if (pData_ && pData_->refCount > 1) {
            std::cout << "  [COW] 引用计数=" << pData_->refCount
                      << "，触发深拷贝" << std::endl;
            --pData_->refCount;
            pData_ = new StringData(pData_->data);
        }
    }

public:
    explicit CowString(const std::string& s = "")
        : pData_(new StringData(s)) {}

    // 拷贝构造：浅拷贝，共享数据
    CowString(const CowString& other) : pData_(other.pData_) {
        addRef();
        std::cout << "  [COW] 浅拷贝，引用计数="
                  << pData_->refCount << std::endl;
    }

    CowString& operator=(const CowString& other) {
        if (this != &other) {
            release();
            pData_ = other.pData_;
            addRef();
        }
        return *this;
    }

    CowString(CowString&& other) noexcept : pData_(other.pData_) {
        other.pData_ = nullptr;
    }

    ~CowString() { release(); }

    // 读取：不需要拷贝
    const std::string& get() const {
        static const std::string empty;
        return pData_ ? pData_->data : empty;
    }

    // 写入：写时复制
    void set(const std::string& s) {
        detach();
        if (!pData_) pData_ = new StringData(s);
        else pData_->data = s;
    }

    int refCount() const { return pData_ ? pData_->refCount : 0; }
};

int main() {
    std::cout << "=== 创建原始字符串 ===" << std::endl;
    CowString s1("Hello, World!");
    std::cout << "s1 = \"" << s1.get()
              << "\", refCount=" << s1.refCount() << std::endl;

    std::cout << "\n=== 浅拷贝赋值 ===" << std::endl;
    CowString s2 = s1;
    std::cout << "s2 = \"" << s2.get()
              << "\", refCount=" << s1.refCount() << std::endl;

    std::cout << "\n=== 再次浅拷贝 ===" << std::endl;
    CowString s3 = s1;
    std::cout << "s3 = \"" << s3.get()
              << "\", refCount=" << s1.refCount() << std::endl;

    std::cout << "\n=== 修改 s2 (触发写时复制) ===" << std::endl;
    s2.set("Modified!");
    std::cout << "s1 = \"" << s1.get()
              << "\", refCount=" << s1.refCount() << std::endl;
    std::cout << "s2 = \"" << s2.get()
              << "\", refCount=" << s2.refCount() << std::endl;
    std::cout << "s3 = \"" << s3.get()
              << "\", refCount=" << s3.refCount() << std::endl;

    return 0;
}
```

**输出：**
```
=== 创建原始字符串 ===
s1 = "Hello, World!", refCount=1

=== 浅拷贝赋值 ===
  [COW] 浅拷贝，引用计数=2
s2 = "Hello, World!", refCount=2

=== 再次浅拷贝 ===
  [COW] 浅拷贝，引用计数=3
s3 = "Hello, World!", refCount=3

=== 修改 s2 (触发写时复制) ===
  [COW] 引用计数=3，触发深拷贝
s1 = "Hello, World!", refCount=2
s2 = "Modified!", refCount=1
s3 = "Hello, World!", refCount=2
```

## 六、代理模式与其他模式的区别

| 模式 | 关键区别 |
|------|---------|
| **装饰器模式（Decorator）** | 装饰器侧重于**动态增加功能**，代理侧重于**控制访问** |
| **适配器模式（Adapter）** | 适配器改变接口以兼容不同接口，代理**保持接口不变** |
| **外观模式（Facade）** | 外观提供简化的接口，代理提供**相同的接口** |

---

## 七、总结

1. **核心思想：** 增加间接层，在不失去透明操作的前提下，实现对对象访问的控制。
2. **接口一致性：** 代理类与真实类遵循同一接口，客户端无感知。
3. **实现差异大：** 不同场景下代理的内部实现可能非常复杂（如分布式代理需要处理网络协议），但设计思想一致。
4. **广泛应用：** 在分布式系统（gRPC Stub、REST SDK）、AOP 框架（安全控制、日志记录）、性能优化（COW、延迟加载）中大量使用。
5. **工具生成：** 在实际工程中，代理类往往由框架或工具自动生成（如 Protobuf 生成的 Stub），而非手工编写。

## 八、补充知识：AOP 与代理

在 **AOP（Aspect Oriented Programming，面向切面编程）** 中，代理模式是实现切面的核心机制。AOP 框架通过为对象生成代理，在方法调用的前后插入额外逻辑（如日志记录、事务管理、权限校验），而无需修改业务代码。

典型的 AOP 使用场景：
- **前置通知（Before）：** 方法执行前的权限检查
- **后置通知（After）：** 方法执行后的日志记录
- **环绕通知（Around）：** 事务的开启与提交

在 C++ 中，虽然没有像 Java Spring 那样成熟的 AOP 框架，但可以通过代理模式手动实现类似效果，或者使用模板元编程实现编译期的 AOP。
