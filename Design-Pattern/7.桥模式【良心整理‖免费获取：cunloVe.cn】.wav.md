# Bridge 桥模式

## 1. 模式概述

Bridge（桥模式）是一种**结构型设计模式**，属于典型的**单一职责模式**。其核心思想是将**抽象部分（Abstraction）**与**实现部分（Implementation）**分离，使它们可以**独立变化**。

- **GoF 定义**：将抽象部分与实现部分分离，使它们都可以独立地变化。
- **本质**：用**组合**代替**继承**，将两个独立变化的维度拆分到不同的类层次结构中。

## 2. 问题动机

### 2.1 多维度变化导致类爆炸

考虑一个消息通信系统 `Message`，需要支持以下功能：

- 用户登录（login）
- 发送消息（sendMessage）
- 发送图片（sendPicture）
- 播放声音（playSound）
- 绘制图形（drawShape）
- 连接网络（connect）

同时需要支持**多个平台**（PC、Mobile）和**多个业务版本**（精简版 Lite、完美版 Perfect）。

### 2.2 继承方案的问题

若采用纯继承方案，类层次结构如下：

```
Message
├── MessagePCBase (PC平台基类)
│   ├── MessagePCLite     (PC精简版)
│   └── MessagePCPerfect  (PC完美版)
└── MessageMobileBase (Mobile平台基类)
    ├── MessageMobileLite     (Mobile精简版)
    └── MessageMobilePerfect  (Mobile完美版)
```

**类的数量**：假设平台维度为 N，业务维度为 M，则总类数为：

$$1 + N + M \times N$$

当 N=5, M=6 时，类数量为 1 + 5 + 30 = **36 个类**，且其中存在大量**结构性重复代码**（如 `MessagePCPerfect` 和 `MessageMobilePerfect` 的业务流程几乎相同，仅平台调用不同）。

### 2.3 核心问题

将两个不同变化方向的函数塞在同一个类继承体系中，会导致：

1. **类急剧膨胀**：子类数量呈乘法增长
2. **充斥重复代码**：不同平台的同版本业务逻辑高度相似
3. **违反单一职责**：一个类同时承担平台实现和业务抽象两种职责

## 3. 解决方案：桥模式

### 3.1 核心思路

**继承转组合**——将两个变化维度拆分为两个独立的类层次：

1. **抽象层**（业务维度）：`Message` → `MessageLite`、`MessagePerfect`
2. **实现层**（平台维度）：`MessageImpl` → `MessagePCImpl`、`MessageMobileImpl`

抽象层通过**多态指针**持有实现层对象，形成"桥接"。

### 3.2 类图

```
                    ┌─────────────────────┐
                    │     Abstraction      │
                    │   (Message 业务抽象)  │
                    │                     │
                    │  - impl_: Impl*     │──────────┐
                    └──────────┬──────────┘          │
                               │                     │
                    ┌──────────┴──────────┐          │
                    │                     │          │
            ┌───────┴───────┐    ┌────────┴───────┐  │
            │  RefineAbsA   │    │   RefineAbsB   │  │
            │ (MessageLite) │    │(MessagePerfect)│  │
            └───────────────┘    └────────────────┘  │
                                                     │
                    ┌─────────────────────┐          │
                    │    Implementor      │          │
                    │ (MessageImpl 平台)   │◄─────────┘
                    └──────────┬──────────┘
                               │
                    ┌──────────┴──────────┐
                    │                     │
            ┌───────┴───────┐    ┌────────┴────────┐
            │ ConcreteImpA  │    │  ConcreteImpB   │
            │(MessagePCImpl)│    │(MessageMobileImpl│
            └───────────────┘    └─────────────────┘
```

### 3.3 类数量对比

| 方案 | 类数量 | 运行时组合数 |
|------|--------|-------------|
| 纯继承 | 1 + N + M×N | M×N |
| 桥模式 | 1 + N + M | N×M（组合） |

类的数量从**乘法关系**变为**加法关系**，大幅减少。

## 4. 实现要点

### 4.1 关键结构

```cpp
// 实现层：平台维度
class MessageImpl {
public:
    virtual ~MessageImpl() = default;
    virtual void connect() = 0;
    virtual void playSound() = 0;
    virtual void writeText(const std::string& text) = 0;
    virtual void drawShape(const std::string& shape) = 0;
};

// 抽象层：业务维度，持有实现层指针
class Message {
protected:
    MessageImpl* impl_;  // 桥接指针
public:
    explicit Message(MessageImpl* impl) : impl_(impl) {}
    virtual ~Message() = default;
    virtual void login() = 0;
    virtual void sendMessage(const std::string& msg) = 0;
    virtual void sendPicture(const std::string& path) = 0;
};
```

### 4.2 运行时装配

```cpp
// 创建平台实现
MessageImpl* pcImpl     = new MessagePCImpl();
MessageImpl* mobileImpl = new MessageMobileImpl();

// 运行时组合：业务版本 + 平台实现
Message* msg1 = new MessageLite(pcImpl);         // PC精简版
Message* msg2 = new MessagePerfect(mobileImpl);   // Mobile完美版
```

与**编译时装配**（继承方案）不同，桥模式实现了**运行时装配**，灵活性更高。

## 5. 完整示例代码

```cpp
#include <iostream>
#include <string>

// ============================================================
// Bridge 模式示例：消息通信系统
// 两个变化维度：
//   1. 平台实现：PC / Mobile
//   2. 业务版本：Lite（精简版）/ Perfect（完美版）
// ============================================================

// ------------------ 实现部分（平台维度）------------------

// MessageImpl: 平台实现的抽象基类
class MessageImpl {
public:
    virtual ~MessageImpl() = default;
    virtual void connect() = 0;
    virtual void playSound() = 0;
    virtual void writeText(const std::string& text) = 0;
    virtual void drawShape(const std::string& shape) = 0;
};

// PC 平台的具体实现
class MessagePCImpl : public MessageImpl {
public:
    void connect() override {
        std::cout << "[PC] 连接网络..." << std::endl;
    }
    void playSound() override {
        std::cout << "[PC] 通过声卡播放声音..." << std::endl;
    }
    void writeText(const std::string& text) override {
        std::cout << "[PC] 在 PC 端口写入文本: " << text << std::endl;
    }
    void drawShape(const std::string& shape) override {
        std::cout << "[PC] 使用 GDI 绘制图形: " << shape << std::endl;
    }
};

// Mobile 平台的具体实现
class MessageMobileImpl : public MessageImpl {
public:
    void connect() override {
        std::cout << "[Mobile] 通过蜂窝网络连接..." << std::endl;
    }
    void playSound() override {
        std::cout << "[Mobile] 通过移动端扬声器播放声音..." << std::endl;
    }
    void writeText(const std::string& text) override {
        std::cout << "[Mobile] 在移动端屏幕写入文本: " << text << std::endl;
    }
    void drawShape(const std::string& shape) override {
        std::cout << "[Mobile] 使用 Canvas 绘制图形: " << shape << std::endl;
    }
};

// ------------------ 抽象部分（业务维度）------------------

// Message: 业务抽象基类，持有 MessageImpl 的指针（Bridge 的关键）
class Message {
protected:
    MessageImpl* impl_;

public:
    explicit Message(MessageImpl* impl) : impl_(impl) {}
    virtual ~Message() = default;

    virtual void login() = 0;
    virtual void sendMessage(const std::string& msg) = 0;
    virtual void sendPicture(const std::string& path) = 0;
};

// 精简版：仅实现基本功能
class MessageLite : public Message {
public:
    using Message::Message;

    void login() override {
        std::cout << "[Lite] 用户登录..." << std::endl;
        impl_->connect();
    }
    void sendMessage(const std::string& msg) override {
        std::cout << "[Lite] 发送消息..." << std::endl;
        impl_->writeText(msg);
    }
    void sendPicture(const std::string& path) override {
        std::cout << "[Lite] 发送图片..." << std::endl;
        impl_->drawShape(path);
    }
};

// 完美版：功能更丰富，附加播放声音等
class MessagePerfect : public Message {
public:
    using Message::Message;

    void login() override {
        std::cout << "[Perfect] 用户登录..." << std::endl;
        impl_->connect();
        impl_->playSound();
    }
    void sendMessage(const std::string& msg) override {
        std::cout << "[Perfect] 发送消息..." << std::endl;
        impl_->playSound();
        impl_->writeText(msg);
    }
    void sendPicture(const std::string& path) override {
        std::cout << "[Perfect] 发送图片..." << std::endl;
        impl_->playSound();
        impl_->drawShape(path);
    }
};

// ------------------ 客户端代码 ------------------

int main() {
    MessageImpl* pcImpl     = new MessagePCImpl();
    MessageImpl* mobileImpl = new MessageMobileImpl();

    std::cout << "========== PC 精简版 ==========" << std::endl;
    Message* liteOnPC = new MessageLite(pcImpl);
    liteOnPC->login();
    liteOnPC->sendMessage("Hello from PC");
    liteOnPC->sendPicture("photo.png");

    std::cout << "\n========== Mobile 完美版 ==========" << std::endl;
    Message* perfectOnMobile = new MessagePerfect(mobileImpl);
    perfectOnMobile->login();
    perfectOnMobile->sendMessage("Hello from Mobile");
    perfectOnMobile->sendPicture("photo.png");

    std::cout << "\n========== PC 完美版 ==========" << std::endl;
    Message* perfectOnPC = new MessagePerfect(pcImpl);
    perfectOnPC->login();
    perfectOnPC->sendMessage("Hello PC Perfect");

    std::cout << "\n========== Mobile 精简版 ==========" << std::endl;
    Message* liteOnMobile = new MessageLite(mobileImpl);
    liteOnMobile->login();
    liteOnMobile->sendMessage("Hello Mobile Lite");

    delete liteOnPC;
    delete perfectOnMobile;
    delete perfectOnPC;
    delete liteOnMobile;
    delete pcImpl;
    delete mobileImpl;

    return 0;
}
```

## 6. 桥模式与 Decorator 模式的对比

两者都涉及"继承转组合"的技巧，但目的不同：

| 特征 | Bridge 桥模式 | Decorator 装饰模式 |
|------|-------------|-------------------|
| **目的** | 分离两个独立变化的维度 | 动态叠加功能/职责 |
| **组合关系** | 抽象层持有实现层指针（1:1） | 装饰器持有被装饰对象（可嵌套） |
| **变化方向** | 两个维度各自独立变化 | 功能层层叠加 |
| **组装时机** | 运行时装配 | 运行时装配 |
| **典型场景** | 跨平台GUI、数据库驱动 | 流式I/O、日志增强 |

## 7. 重构手法：继承转组合

桥模式的推导过程体现了经典的**重构手法**：

1. **识别多个变化维度**：将函数按变化方向分组
2. **提取实现类**：将其中一个维度的函数提取为独立的实现类层次
3. **继承转组合**：在抽象类中用指针/引用持有实现类对象
4. **字段上提**：将子类共有的字段上提到基类（Martin Fowler 重构原则）

关键步骤：
```
// 重构前：继承
class MessagePCPerfect : public MessagePCBase { ... };

// 重构后：组合
class MessagePerfect : public Message {
    MessageImpl* impl_;  // 原来通过继承获得的平台能力，现在通过组合
};
```

## 8. 适用场景与注意事项

### 适用场景

- 一个类存在**两个或多个独立变化的维度**
- 不希望使用多重继承（违背单一职责原则，复用性差）
- 需要在**运行时切换**实现

### 注意事项

1. 桥模式最适合**两个强变化维度**的场景
2. 若有**三个以上变化维度**，可将其中多个维度合并为一个实现层，或使用多个桥接指针
3. C++ 中推荐**单继承 + 组合**的方式，而非多继承
4. 需要注意实现层对象的**生命周期管理**（可考虑使用智能指针）

## 9. 总结

桥模式的核心价值：

- **解耦**抽象与实现之间的固有绑定关系
- **类数量**从乘法关系（1+N+M×N）降为加法关系（1+N+M）
- **运行时装配**实现灵活组合，而非编译时硬编码
- 遵循**单一职责原则**，每个类只负责一个变化维度
- 与 Decorator 模式同属"继承转组合"的典型应用，但解决的问题不同
