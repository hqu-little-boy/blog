# 抽象工厂模式 (Abstract Factory)

## 1. 概述

抽象工厂模式是一种**创建型设计模式**，用于创建一系列相互依赖或相互关联的对象，而无需指定它们的具体类。

### 1.1 核心思想

- 绕开 `new` 操作符，避免将代码绑定到具体类
- 提供一个接口，负责创建**一系列**相互关联的对象
- 确保同一系列的对象被一起创建，保证它们之间的兼容性

### 1.2 与工厂方法的关系

| 特性 | 工厂方法 | 抽象工厂 |
|------|----------|----------|
| 创建对象数量 | 单一对象 | 一系列相关对象 |
| 复杂度 | 较低 | 较高 |
| 适用场景 | 单对象变化 | 多系列对象变化 |
| 关系 | 工厂方法是抽象工厂的特例 | 抽象工厂是工厂方法的推广 |

## 2. 问题场景

### 2.1 数据库访问层示例

假设需要开发一个数据访问层，支持多种数据库：

- **SQL Server**: SqlConnection, SqlCommand, SqlDataReader
- **Oracle**: OracleConnection, OracleCommand, OracleDataReader
- **MySQL**: MySqlConnection, MySqlCommand, MySqlDataReader

### 2.2 直接使用 new 的问题

```cpp
// 直接绑定到具体类，无法灵活切换数据库
auto conn = new SqlConnection();      // 绑定 SQL Server
auto cmd = new SqlCommand();          // 绑定 SQL Server
auto reader = new SqlDataReader();    // 绑定 SQL Server
```

**问题**：
- 代码与具体数据库实现紧密耦合
- 切换数据库需要修改多处代码
- 违反开闭原则

### 2.3 使用工厂方法的不足

使用工厂方法模式可以解决单个对象的创建问题：

```cpp
// 每种对象一个工厂
IDBConnectionFactory* connFactory;
IDBCommandFactory* cmdFactory;
IDBDataReaderFactory* readerFactory;
```

**潜在问题**：
- 三个工厂可能被错误地传递不同系列的实现
- 例如：SQL Server 的 Connection + Oracle 的 Command + MySQL 的 Reader
- 这会导致运行时错误，因为不同系列的对象不能协同工作

## 3. 解决方案：抽象工厂

### 3.1 核心改进

将**三个工厂合并为一个工厂**，确保同一系列的对象被一起创建：

```cpp
class IDBFactory {
public:
    virtual IDBConnection* createConnection() = 0;
    virtual IDBCommand* createCommand() = 0;
    virtual IDBDataReader* createDataReader() = 0;
};
```

### 3.2 优势

1. **保证系列一致性**: 同一个工厂创建的对象属于同一系列
2. **简化客户端**: 只需传递一个工厂对象
3. **高内聚低耦合**: 相关对象的创建逻辑集中管理

## 4. 模式结构

### 4.1 UML 类图

```
┌─────────────────────────────┐
│     <<interface>>           │
│       IDBFactory            │  ← AbstractFactory (稳定)
│                             │
│  + createConnection()       │
│  + createCommand()          │
│  + createDataReader()       │
└─────────────┬───────────────┘
              │
    ┌─────────┴─────────┐
    │                   │
    ▼                   ▼
┌──────────────┐  ┌──────────────┐
│SqlServer     │  │ Oracle       │  ← ConcreteFactory (变化)
│DBFactory     │  │ DBFactory    │
└──────────────┘  └──────────────┘

┌───────────┬───────────┬───────────┐
│IDBConnection│IDBCommand│IDBDataReader│  ← AbstractProduct (稳定)
└─────┬─────┴─────┬─────┴─────┬─────┘
      │           │           │
   ┌──┴──┐     ┌──┴──┐     ┌──┴──┐
   │SQL  │     │SQL  │     │SQL  │      ← ConcreteProduct (变化)
   │Conn │     │Cmd  │     │Reader│
   ├─────┤     ├─────┤     ├──────┤
   │Oracle│    │Oracle│    │Oracle│
   │Conn │     │Cmd  │     │Reader│
   └─────┘     └─────┘     └──────┘
```

### 4.2 角色说明

| 角色 | 说明 | 示例 |
|------|------|------|
| AbstractFactory | 声明创建产品的接口 | IDBFactory |
| ConcreteFactory | 实现创建具体产品的操作 | SqlServerDBFactory, OracleDBFactory |
| AbstractProduct | 声明产品接口 | IDBConnection, IDBCommand, IDBDataReader |
| ConcreteProduct | 实现具体产品 | SqlConnection, OracleCommand 等 |

## 5. 完整代码示例

```cpp
#include <iostream>
#include <memory>
#include <string>

// ============ 抽象产品A：数据库连接 ============
class IDBConnection {
public:
    virtual ~IDBConnection() = default;
    virtual void connect(const std::string& connectionString) = 0;
    virtual std::string getConnectionInfo() const = 0;
};

// ============ 抽象产品B：数据库命令 ============
class IDBCommand {
public:
    virtual ~IDBCommand() = default;
    virtual void setConnection(std::shared_ptr<IDBConnection> conn) = 0;
    virtual void execute(const std::string& sql) = 0;
};

// ============ 抽象产品C：数据读取器 ============
class IDBDataReader {
public:
    virtual ~IDBDataReader() = default;
    virtual void read() = 0;
};

// ============ 抽象工厂：数据库工厂 ============
class IDBFactory {
public:
    virtual ~IDBFactory() = default;
    virtual std::shared_ptr<IDBConnection> createConnection() = 0;
    virtual std::shared_ptr<IDBCommand> createCommand() = 0;
    virtual std::shared_ptr<IDBDataReader> createDataReader() = 0;
};

// ============ SQL Server 系列产品 ============
class SqlConnection : public IDBConnection {
public:
    void connect(const std::string& connectionString) override {
        std::cout << "[SQL Server] 连接到: " << connectionString << std::endl;
    }
    std::string getConnectionInfo() const override {
        return "SQL Server Connection";
    }
};

class SqlCommand : public IDBCommand {
    std::shared_ptr<IDBConnection> conn_;
public:
    void setConnection(std::shared_ptr<IDBConnection> conn) override {
        conn_ = conn;
        std::cout << "[SQL Server] 命令绑定连接: " << conn_->getConnectionInfo() << std::endl;
    }
    void execute(const std::string& sql) override {
        std::cout << "[SQL Server] 执行SQL: " << sql << std::endl;
    }
};

class SqlDataReader : public IDBDataReader {
public:
    void read() override {
        std::cout << "[SQL Server] 读取数据" << std::endl;
    }
};

// ============ Oracle 系列产品 ============
class OracleConnection : public IDBConnection {
public:
    void connect(const std::string& connectionString) override {
        std::cout << "[Oracle] 连接到: " << connectionString << std::endl;
    }
    std::string getConnectionInfo() const override {
        return "Oracle Connection";
    }
};

class OracleCommand : public IDBCommand {
    std::shared_ptr<IDBConnection> conn_;
public:
    void setConnection(std::shared_ptr<IDBConnection> conn) override {
        conn_ = conn;
        std::cout << "[Oracle] 命令绑定连接: " << conn_->getConnectionInfo() << std::endl;
    }
    void execute(const std::string& sql) override {
        std::cout << "[Oracle] 执行SQL: " << sql << std::endl;
    }
};

class OracleDataReader : public IDBDataReader {
public:
    void read() override {
        std::cout << "[Oracle] 读取数据" << std::endl;
    }
};

// ============ MySQL 系列产品 ============
class MySqlConnection : public IDBConnection {
public:
    void connect(const std::string& connectionString) override {
        std::cout << "[MySQL] 连接到: " << connectionString << std::endl;
    }
    std::string getConnectionInfo() const override {
        return "MySQL Connection";
    }
};

class MySqlCommand : public IDBCommand {
    std::shared_ptr<IDBConnection> conn_;
public:
    void setConnection(std::shared_ptr<IDBConnection> conn) override {
        conn_ = conn;
        std::cout << "[MySQL] 命令绑定连接: " << conn_->getConnectionInfo() << std::endl;
    }
    void execute(const std::string& sql) override {
        std::cout << "[MySQL] 执行SQL: " << sql << std::endl;
    }
};

class MySqlDataReader : public IDBDataReader {
public:
    void read() override {
        std::cout << "[MySQL] 读取数据" << std::endl;
    }
};

// ============ 具体工厂 ============
class SqlServerDBFactory : public IDBFactory {
public:
    std::shared_ptr<IDBConnection> createConnection() override {
        return std::make_shared<SqlConnection>();
    }
    std::shared_ptr<IDBCommand> createCommand() override {
        return std::make_shared<SqlCommand>();
    }
    std::shared_ptr<IDBDataReader> createDataReader() override {
        return std::make_shared<SqlDataReader>();
    }
};

class OracleDBFactory : public IDBFactory {
public:
    std::shared_ptr<IDBConnection> createConnection() override {
        return std::make_shared<OracleConnection>();
    }
    std::shared_ptr<IDBCommand> createCommand() override {
        return std::make_shared<OracleCommand>();
    }
    std::shared_ptr<IDBDataReader> createDataReader() override {
        return std::make_shared<OracleDataReader>();
    }
};

class MySqlDBFactory : public IDBFactory {
public:
    std::shared_ptr<IDBConnection> createConnection() override {
        return std::make_shared<MySqlConnection>();
    }
    std::shared_ptr<IDBCommand> createCommand() override {
        return std::make_shared<MySqlCommand>();
    }
    std::shared_ptr<IDBDataReader> createDataReader() override {
        return std::make_shared<MySqlDataReader>();
    }
};

// ============ 客户端代码：面向接口编程 ============
class DataAccessLayer {
    std::shared_ptr<IDBFactory> factory_;
    std::shared_ptr<IDBConnection> connection_;
    std::shared_ptr<IDBCommand> command_;
    std::shared_ptr<IDBDataReader> reader_;

public:
    explicit DataAccessLayer(std::shared_ptr<IDBFactory> factory)
        : factory_(factory) {}

    void initialize(const std::string& connStr) {
        connection_ = factory_->createConnection();
        command_ = factory_->createCommand();
        reader_ = factory_->createDataReader();

        connection_->connect(connStr);
        command_->setConnection(connection_);
    }

    void query(const std::string& sql) {
        command_->execute(sql);
        reader_->read();
    }
};

int main() {
    std::cout << "=== 使用 SQL Server ===" << std::endl;
    auto sqlFactory = std::make_shared<SqlServerDBFactory>();
    DataAccessLayer dal1(sqlFactory);
    dal1.initialize("Server=localhost;Database=TestDB");
    dal1.query("SELECT * FROM Users");

    std::cout << "\n=== 使用 Oracle ===" << std::endl;
    auto oracleFactory = std::make_shared<OracleDBFactory>();
    DataAccessLayer dal2(oracleFactory);
    dal2.initialize("Host=localhost;SID=ORCL");
    dal2.query("SELECT * FROM Employees");

    std::cout << "\n=== 使用 MySQL ===" << std::endl;
    auto mysqlFactory = std::make_shared<MySqlDBFactory>();
    DataAccessLayer dal3(mysqlFactory);
    dal3.initialize("host=localhost;dbname=shop");
    dal3.query("SELECT * FROM Products");

    return 0;
}
```

## 6. 关键设计要点

### 6.1 依赖注入

客户端代码通过构造函数接收工厂对象，实现了依赖注入：

```cpp
explicit DataAccessLayer(std::shared_ptr<IDBFactory> factory)
    : factory_(factory) {}
```

### 6.2 系列一致性保证

使用同一个工厂创建所有产品，确保它们属于同一系列：

```cpp
void initialize(const std::string& connStr) {
    // 全部由同一个工厂创建，保证系列一致
    connection_ = factory_->createConnection();
    command_ = factory_->createCommand();
    reader_ = factory_->createDataReader();
}
```

### 6.3 产品间的依赖关系

某些产品之间存在依赖关系，例如 Command 需要绑定 Connection：

```cpp
command_->setConnection(connection_);
```

## 7. 适用场景

### 7.1 适合使用抽象工厂的情况

1. **多系列对象**: 系统需要支持多个系列的产品（如多种数据库）
2. **系列内关联**: 同一系列的产品之间存在依赖或关联关系
3. **系列间隔离**: 不同系列的产品不能混用
4. **频繁切换系列**: 需要在运行时切换整个产品系列

### 7.2 不适合使用的情况

1. **单一系列**: 只有一个产品系列，使用简单工厂即可
2. **产品无关联**: 产品之间没有依赖关系
3. **频繁新增产品**: 需要经常添加新的产品类型（违反开闭原则）

## 8. 优缺点分析

### 8.1 优点

| 优点 | 说明 |
|------|------|
| 系列一致性 | 保证同一系列的产品被一起使用 |
| 易于切换 | 切换整个产品系列只需更换工厂 |
| 符合开闭原则 | 新增系列无需修改现有代码 |
| 解耦客户端 | 客户端只依赖抽象接口 |

### 8.2 缺点

| 缺点 | 说明 |
|------|------|
| 扩展产品困难 | 新增产品类型需要修改抽象工厂接口 |
| 类数量增加 | 每个系列都需要对应的工厂类 |
| 复杂度提升 | 相比简单工厂，结构更复杂 |

## 9. 与其他模式的关系

### 9.1 工厂方法

- 工厂方法是抽象工厂的特例
- 当抽象工厂只创建一个产品时，退化为工厂方法

### 9.2 单例模式

- 工厂通常是单例，确保全局唯一

### 9.3 建造者模式

- 建造者关注对象的构建过程
- 抽象工厂关注产品系列的选择

## 10. 总结

抽象工厂模式的核心价值在于：

1. **解决系列对象的创建问题**: 确保同一系列的对象被一起创建
2. **保证对象间的兼容性**: 避免不同系列的对象混用导致错误
3. **支持灵活切换**: 可以轻松切换整个产品系列

**设计模式的本质**：在稳定中寻找变化点，将变化封装起来。抽象工厂将"产品系列的选择"这一变化点封装在工厂中。

**重要原则**：
- 没有万能的设计模式
- 每个模式都有其适用场景和局限性
- 设计模式解决的是"稳定中有变化"的场景
